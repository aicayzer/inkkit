# Host API

This reference describes the public facade. Host policies and command availability require 0.0.8 or later; native text ranges and viewport coordination require 0.0.9 or later. Check the [releases](https://github.com/aicayzer/inkkit/releases) for verified published versions.

`InkKitEditor.mount(root, events, options?: EditorOptions)` creates the editor. `events` needs the `changed`, `stateChanged`, `openLink` and `copy` handlers; `commandStateChanged`, `error` and `clipboard` are optional. `EditorOptions` accepts optional `images`, `files`, `wikiLinks`, `editable`, `textInput`, `labels`, `keymap` and `rendering`. Editing defaults to enabled; omitted text-input preferences retain browser behaviour. Import `@aicayzer/inkkit/style.css` into the host bundle. Keep the root alive until `destroy()` completes.

`loadDocument({ documentId, generation, format, text })` loads Markdown (`md`) or literal text (`txt`). Increment the generation when replacing a document. `reloadDocument(input)` retains the caret, scroll position and Markdown editing mode for an external reload.

`snapshot(expectedGeneration?)` returns the complete current text, format, document ID, generation, revision and dirty state. It throws for a missing document, composition, pending image operations, stale generations or a destroyed editor. A snapshot failure is not an unchanged document. Formatted edits are validated before they reach the view. If preservation fails, the edit is refused: the facade call that made it throws `preservation`, and an edit the person makes is reported through `events.error`. The visible document, snapshot, revision and undo history remain unchanged, and `changed` is not emitted for the refused edit. Save, close, switching and Copy as Markdown must capture a fresh snapshot before changing native state.

`await printableSnapshot(expectedGeneration?)` returns a `PrintableDocument` for the whole current document, independent of selection, viewport, folding and comment visibility. It contains document ID, generation, revision, format, a complete standalone `html` document with embedded print CSS, the same CSS in `styles`, portable `assets` in HTML image order, and explicit `warnings` for Mermaid source fallbacks. Assets contain owned byte copies. Metadata and result arrays are frozen; asset bytes belong to the caller. The output includes footnotes, resolved reference links, tables, images, Mermaid, full callout bodies and highlights. It excludes author comments, clipboard provenance and editor controls. TXT remains escaped literal text.

Printing captures a fresh snapshot and rechecks document identity, generation and revision after asynchronous work, including edit/undo or reload during export. Composition, pending imports, stale documents and destruction reject the operation. Missing, empty, mismatched or undecodable authored image bytes reject with `image-unavailable`. Invalid or unsupported Mermaid prints readable code with a `diagram-unavailable` warning; failure to rasterise a successfully rendered diagram rejects with `diagram-unavailable`. No failed operation returns partial printable content. Local `blob:` image permission is required during portable asset validation; the returned HTML uses only `data:` images. Client apps own Print/PDF commands, dialogs, file generation and file access.

Print styles wrap long text and tables and fit images within the available width and 90% of the print viewport height while preserving their aspect ratio. Client apps can adapt these styles to their paper and layout requirements.

`clipboardSnapshot(all = true)` returns a whole-document or current-selection export with readable text, semantic HTML, Markdown source and portable image results. Resolve it before touching the native clipboard, check document identity, and retain the existing clipboard on failure. `paste({ text, markdown?, html?, images?, plainText? })` captures one operation; do not reread the global clipboard after awaiting it. Optional `markdown` explicitly supplies source, taking precedence over text and HTML semantics; HTML remains available for portable image bytes. `pasteAsPlainText(text)` inserts literal text.

Mermaid previews leave code source editable. Clipboard output adds `diagrams`, with each complete diagram's source, optional portable PNG and optional error. Successful PNGs also appear in `images` in HTML order, so existing native attachment bridges can export them. Generated diagrams have an empty image reference and do not use the host image adapter. `events.error` reports `diagram-unavailable` when a preview fails. A diagram that cannot be exported has an `error` in `diagrams` and keeps readable source in rich output; clipboard output that describes its own failures is not also reported as an error. Partial code selections produce source rather than a rendered diagram. Hosts enforcing a Content Security Policy must permit local `blob:` image URLs for diagram rasterisation. A blocked decoder reports a diagram export failure and retains source.

`format(command, options?, expectedGeneration?)`, `table(command, options?, expectedGeneration?)`, `find(text)`, `focus()` and `setKeymap(bindings)` implement host controls; [Formatting and keys](#formatting-and-keys) describes `format` and `keyDown`. Table commands include insert, row/column addition and deletion, alignment and exit. Default inserted tables have three rows and two columns. `insertText` and `keyDown` take a generation for buffered native input; composition leaves buffered input unhandled.

`insertPaths(paths, at, expectedGeneration?)` places literal paths at the drop point `at`, a `ClientPoint`, and returns `false` only for an empty list. `insertImages(images, at?, expectedGeneration?)` inserts already-stored references; see [Inserting images](#inserting-images). `destroy()` cancels pending work and releases the editor.

## Errors

Every failure InkKit reports is an `InkKitError`. Branch on its `code`, which is one of the values in the following table; the `message` is for logs. When the failure started elsewhere, such as in an adapter, the host clipboard or the diagram renderer, the original error is `cause`.

| Code                    | Raised when                                                                                                                                                                                                                                                                                                                                                                               | Arrives as                                                                                                           | Retry                                                                                                         |
| ----------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| `not-ready`             | A document method is called before the first `loadDocument`.                                                                                                                                                                                                                                                                                                                              | Thrown; rejected by async methods.                                                                                   | Yes, after `loadDocument`.                                                                                    |
| `destroyed`             | Any method is called after `destroy()`, except `destroy()` itself, which does nothing.                                                                                                                                                                                                                                                                                                    | Thrown; rejected.                                                                                                    | Never.                                                                                                        |
| `stale-document`        | The expected generation is not the loaded one; a text range or heading comes from an older snapshot; or the document changed while asynchronous work, such as a copy, print, image import or deferred cut, was running.                                                                                                                                                                   | Thrown; rejected; `events.error` for a deferred cut and late image imports.                                          | Not with the same generation or range. Read the state again and act again if it still applies.                |
| `composition`           | Text composition (IME) is active and the call would read or change the document, or change editability or input preferences. `commandState()` doesn't raise it.                                                                                                                                                                                                                           | Thrown; rejected.                                                                                                    | Yes, after `commandStateChanged` reports `composing: false`.                                                  |
| `operation-pending`     | An image import is still running.                                                                                                                                                                                                                                                                                                                                                         | Thrown; rejected.                                                                                                    | Yes, after `commandStateChanged` reports `pending: false`.                                                    |
| `read-only`             | A mutating method is called while `editable` is `false`.                                                                                                                                                                                                                                                                                                                                  | Thrown; rejected.                                                                                                    | Yes, after `setEditable(true)`.                                                                               |
| `invalid-argument`      | A parameter has the wrong type or is outside its documented range: an unknown mode, command, keymap name or option; text that is not a string; a table size outside 1 to 100; a sort column that does not exist; a footnote label that cannot be saved; a value that is not a heading entry; a viewport container that is not the root or an ancestor; or a negative or non-finite inset. | Thrown; rejected.                                                                                                    | Never with the same arguments; it's a host defect.                                                            |
| `invalid-range`         | A current text range can't be used: it splits a surrogate pair or a protected label, or a replacement crosses an embed, a hard break, a hidden comment or a block boundary.                                                                                                                                                                                                               | Thrown.                                                                                                              | Not with the same range.                                                                                      |
| `preservation`          | An edit would save Markdown that doesn't reopen as shown, so it's refused; or `snapshot()` or a selection copy can't serialize the current content.                                                                                                                                                                                                                                       | Thrown by the call that made the edit; rejected by `clipboardSnapshot()`; `events.error` for edits the person makes. | Never for the same edit on the same content. After a failed snapshot, don't save, and keep the document open. |
| `image-unavailable`     | Portable image bytes can't be obtained: print finds an authored image with no adapter or bad bytes; a paste or drop imports an image the adapter refused, and a placeholder is inserted instead; or a cut is refused because a selected image can't be copied.                                                                                                                            | Rejected by `printableSnapshot()`; `events.error`.                                                                   | Yes, if the host can supply the bytes later.                                                                  |
| `diagram-unavailable`   | A Mermaid diagram can't be previewed, print can't rasterize one that previewed, or a cut is refused because a selected diagram can't be copied.                                                                                                                                                                                                                                           | Rejected by `printableSnapshot()`; `events.error`.                                                                   | Not expected to succeed; the source is kept.                                                                  |
| `file-unavailable`      | A file or wiki link can't be resolved, shown or opened: `FileAdapter.resolve` rejects or returns an invalid presentation, a resolved media resource fails to load, or `WikiLinkAdapter.resolve`, `WikiLinkAdapter.open`, `FileAdapter.open` or `FileAdapter.contextMenu` throws.                                                                                                          | `events.error`.                                                                                                      | Yes, with the card's Retry button, or once the host can resolve it.                                           |
| `clipboard-unavailable` | Images or diagrams were copied or cut without an `events.clipboard` handler, or `events.clipboard` threw or rejected. A cut removes nothing.                                                                                                                                                                                                                                              | `events.error`.                                                                                                      | Yes, once the host can write the clipboard.                                                                   |
| `internal`              | An unexpected exception inside InkKit. It's a defect, never a designed outcome; the exception is `cause`.                                                                                                                                                                                                                                                                                 | Thrown; rejected; `events.error`.                                                                                    | No. Report it, keep the document open, and take a fresh snapshot before trusting the editor's state.          |

How a failure arrives:

- **Synchronous methods throw.** A thrown `InkKitError` means that the call changed nothing and sent nothing: the document, selection, revision and undo history are as they were before the call, and no `changed`, `stateChanged` or `commandStateChanged` event was sent for it. The one exception is `internal`, after which the editor's state can't be trusted. When a call succeeds, those events arrive in order just before it returns; an asynchronous method sends the ones it raises after its first pause as they happen. If your handler for one of them makes a call that sends a newer event of the same kind, the older ones still waiting aren't sent. `mount`, `printableSnapshot`, `clipboardSnapshot`, `paste` and `destroy` never throw; they return a promise that rejects. `destroy()` never rejects.
- **A failure goes to the caller and nowhere else.** When the preservation check refuses an edit that a facade call makes, such as `insertText`, `pasteAsPlainText`, `format` or `paste`, the call throws or rejects with `preservation`, and `events.error` isn't called.
- **`events.error` is for failures that no call is waiting for:** edits the person makes (typing, shortcuts, DOM paste, drop and cut), background presentation work (diagram previews and file and wiki-link resolution), DOM copy and cut, and images that a finished paste or drop couldn't import. It always receives an `InkKitError`.
- **Results describe partial outcomes.** `false` means that the call didn't apply here. Degraded output describes itself, in `ClipboardOutput.images[].error`, `ClipboardOutput.diagrams[].error` and `PrintableDocument.warnings`, and isn't also reported as an error.
- **An exception from your own event handler stays yours.** When `changed`, `stateChanged`, `commandStateChanged`, `openLink`, `copy` or `error` throws, InkKit passes the exception to the platform's `reportError()` and carries on, so it never becomes an `InkKitError` and never makes a call throw. A `clipboard` handler that throws or rejects is `clipboard-unavailable`.
- **Checks run in a fixed order.** `destroyed` comes first, then `invalid-argument`, then the document's state: `not-ready`, `stale-document`, `composition`, `operation-pending` and `read-only`.
- **`null` means omitted** for an optional parameter or option field, because WebKit bridges send JSON `null` for a missing value. For example, `snapshot(null)` reads the current generation, and a keymap entry of `null` keeps that name's default bindings.

Any `InkKitError` except `destroyed` and `internal` leaves the editor usable.

## Editability and text input

`editable` returns the current editing policy. `setEditable(boolean)` changes it on both formatted and source/TXT surfaces. `setTextInputPreferences(preferences: TextInputPreferences)` replaces the preferences and updates native HTML input attributes on both surfaces. Omitted fields remove explicit attributes rather than retaining earlier overrides. `TextInputPreferences` contains optional `spellcheck: boolean`, `autocorrect: boolean` and `autocapitalize: 'off' | 'none' | 'on' | 'sentences' | 'words' | 'characters'`. Omitted preferences leave behaviour to the browser; these are input preferences rather than guarantees of OS behaviour.

Read-only permits selection, copying, find, navigation, folding and formatted/source switching. Host document loading and reloading remain explicit host operations. Mutating facade calls reject with `InkKitError` code `read-only`; typing, paste/drop, cut completion, task toggles, table controls, reference editing and resizing cannot change content. Undo/redo are disabled while read-only, retaining history for later re-enabling.

Entering read-only cancels pending imports and invalidates deferred destructive operations, including acknowledged Cut. A late result cannot mutate the editor after editing is re-enabled. Active image resize previews are cancelled. Imported asset retention and cleanup remain the host adapter's responsibility.

Editability and input-preference transitions reject during active composition with code `composition` and no partial change. Successful changes preserve focus, selection, source, document identity, revision, dirty state and shared history. These transitions are presentation changes, not document edits.

## Command availability

`commandState(expectedGeneration?)` returns the current `CommandState` without dispatching edits or changing history. A missing document, stale expected generation or destroyed editor rejects the query. Unlike a save snapshot, availability remains readable during composition and pending imports, with affected commands disabled.

The state contains `documentId`, `generation`, `revision`, `format`, `mode`, `editable`, `composing`, `pending`, `caret: CaretState`, optional `table` context (`row`, `column`, `rows`, `columns`) and `commands`. The command booleans cover `undo`, `redo`, `insertText`, `paste`, `replace`, `replaceSource`, `insertImages`, `insertPaths`, `insertFootnote` and `editReferenceDefinition`; `commands.format` maps each `FormatCommand`, by the same names `format` takes, to availability, and `commands.table` maps each `TableCommand`. Row and column indices are zero-based.

The optional `events.commandStateChanged(state)` callback publishes current state after selection, editing, history, mode or input-policy changes and after document replacement. Document loading suppresses intermediate state. The existing `events.stateChanged(CaretState)` contract is retained for active formatting.

Source and TXT disable formatted commands. Read-only disables mutations while retaining non-mutating operations. Availability is contextual: recheck generation and handle the operation's result/errors when a user acts. The host owns toolbar/menu presentation; querying availability never dirties the document.

## Formatting and keys

`format(command, options?, expectedGeneration?)` applies one `FormatCommand` to the selection in formatted mode and returns whether the document, or the marks the next typed text takes, changed. It returns `false` in source and TXT modes and when the command has nothing to change. In formatted mode, `format` focuses the editor.

| Command                                                | Effect                                                                                                                                                   |
| ------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `heading1` to `heading6`                               | Makes the block a heading of that level. Applying the block's current level makes it a paragraph again.                                                  |
| `paragraph`                                            | Makes the block a paragraph.                                                                                                                             |
| `bold`, `italic`, `strikethrough`, `highlight`, `code` | Toggles the mark on the selection. At a caret, toggles it for the text typed next; `code` inside a code span removes the span.                           |
| `codeBlock`                                            | Makes the block a code block, with the info string `options.language` when given, or makes a code block a paragraph again.                               |
| `quote`                                                | Quotes the selected blocks, or the whole list when the selection is in a list item, or removes the quote that holds them.                                |
| `bulletList`, `orderedList`                            | Makes the blocks a list of that kind, converts a list of the other kind, or lifts the item out of a list of the same kind.                               |
| `taskList`                                             | Makes the selected list items tasks, making the blocks a bullet list first when they aren't in one, or makes them ordinary items when they're all tasks. |
| `link`                                                 | With `options.destination`, sets the link. Without it, removes the link. See the following list.                                                         |

`FormatOptions` has two optional fields: `destination`, only with `link`, and `language`, only with `codeBlock`. Any other option, or an option with another command, throws `invalid-argument`, as does an unknown command. `null` counts as omitted.

A link destination, in `format('link', { destination })` and in `editReferenceDefinition`, must be one that the editor would open and can save. It throws `invalid-argument` when it's empty or only spaces; when it isn't relative, a fragment, a query, or an `http`, `https`, `mailto` or `tel` address, the same list that [opening links](#opening-links) uses; when it contains a control character, such as a line break; or when Markdown can't write it so that it reads back the same, such as `<x>`. Spaces, parentheses and non-ASCII characters are written in a form that reads back as given.

`link` works on the link that holds the caret, including a caret just before its first character, or that holds the whole selection:

- **With a destination,** an inline link keeps its text and title and takes the new destination. An autolink given a new destination becomes an inline link with the same text. In a reference link, the shared definition is edited instead, as `editReferenceDefinition` does, so every link that uses that definition changes. A selection that isn't inside one link becomes a link to the destination, replacing the links in the selected text; at a caret outside a link, the text typed next is linked. Giving a link the destination it already has returns `false` and changes nothing, so an autolink keeps its form.
- **Without a destination,** the whole link is removed and its text stays. A selection that isn't inside one link removes the links from the selected text; the part of a link outside the selection stays a link. If there is no link to remove, `format` returns `false` and changes nothing.

At a caret, marks toggled for the text typed next, such as `bold`, stay toggled after the link changes.

`keyDown(input: KeyInput, expectedGeneration)` passes a key that the host's native input received to InkKit, as if it were pressed in the editor. `KeyInput` is `{ key, code?, metaKey?, ctrlKey?, altKey?, shiftKey? }`, with the `KeyboardEvent` meanings; an omitted or `null` modifier isn't held. It returns `true` when InkKit handled the key, and then the host mustn't also handle it natively; `false` means the host's native handling applies. The expected generation is required. During composition with the current generation, `keyDown` returns `false`. InkKit handles:

- The bindings from `setKeymap`, including history and table bindings, in every mode where they apply.
- **Alt+Enter** and **Alt+Shift+Enter** in formatted mode, which move between a footnote reference and its definition, as `navigateFootnote` does.
- In formatted mode, every other key reaches the editor's own key handling, such as Enter, Tab and Backspace in lists and tables.
- In source and TXT modes, Enter, Tab, Backspace and Delete edit the text; other keys return `false`.
- When the editor is read-only, any bound key throws `read-only`, and so do Enter, Tab, Backspace and Delete. The exception is formatted mode, where Tab and Shift+Tab move between table cells, and return `false` outside a table.

## Native readable text and layout

From 0.0.9, `textSnapshot(expectedGeneration?)` returns an immutable readable-text snapshot with an opaque `snapshotId`, document identity, generation, revision, format, mode, text and current UTF-16 selection. Keep ranges as `{ snapshotId, from, to }`; `from` and `to` are zero-based, half-open UTF-16 offsets in that snapshot’s `text`. They are not raw Markdown offsets or ProseMirror positions. Hosts continue to own search queries and controls.

Source and TXT expose displayed textarea text, with CRLF normalised to LF. The ordinary `snapshot()` still contains the exact authored source. Formatted snapshots join textblocks and hard breaks with LF. Readable image alt text, footnote labels and callout titles are protected content; author comments and reference-definition metadata are excluded. Footnote definition bodies remain readable text. Empty image alt text uses `Image`; callout labels use their title or kind. Folded bodies remain in logical text, while hidden content has no current rectangles.

`selectTextRange(range, options?)`, `revealTextRange(range)` and `replaceTextRange(range, text)` use that same mapping. Selection preserves host focus unless explicitly requested. Complete protected image and footnote labels select their atomic node; a complete callout title selects the callout block, so the returned effective selection includes its body. Partial protected labels reject. Reveal may unfold a folded ancestor and scroll to the range. Replacement is literal, retains surrounding structure and inline marks, and forms one shared undo step. Replacement rejects protected embeds, existing hard breaks, hidden comments and cross-block boundaries before editing; use source mode for source syntax. Offsets that split a surrogate pair, partial protected labels and unsupported replacement boundaries reject with `invalid-range`. Invalid viewport containers or non-finite/negative insets throw `invalid-argument` before changing layout policy.

Reloads, document replacements, revisions and mode changes invalidate old snapshot IDs, including reloads with otherwise identical generation/revision and mode round trips. IDs are editor-local. Caret changes, scrolling, insets and resizing do not invalidate unchanged text. Read-only permits selection and reveal but rejects replacement. Text snapshots, selection and geometry reject during composition or pending operations, as well as after destruction or before a document is ready. Capture a new text snapshot after an edit or a stale-range rejection.

`textRangeRects(range)` computes geometry only when requested. `textRangesRects(ranges)` measures a batch in input order, using one temporary layout for source/TXT. It validates the complete batch before measurement, returns frozen rectangle arrays and retains no layout cache; an empty batch returns an empty array. Use it for native character geometry instead of querying each character separately. `visibleTextRanges(snapshotId)` returns currently visible logical ranges. Rectangles use CSS pixels in the web view’s client coordinate space, with the same origin as DOM pointer/drop coordinates. They are not device pixels or coordinates relative to the mounted root. Hosts translate them at their native bridge boundary.

`setViewport({ scrollContainer?, insets? })` identifies the host-owned scroll container and overlapping chrome insets. The mounted root is the default scroll container. Insets are non-negative CSS pixels on each edge of its visible viewport; `viewport()` reports the resulting visible rectangle, insets and combined scroll offsets. Rectangle fields are `left`, `top`, `right`, `bottom`, `width` and `height`. Source/TXT retain the textarea’s internal scrolling. Explicit range reveal, find and heading navigation share this viewport contract. Layout and headers stay in the host.

Loading releases focus from the editor's active text surface and does not reveal a saved caret. It leaves other host controls focused. Call `focus()` after loading only when editing should start immediately. External reloads preserve valid selection, focus and scroll positions without jumping a browsing host. Explicit focus/navigation may reveal the caret. Each editor retains its own text identities, viewport and layout state.

## Footnotes and reference links

`insertFootnote(label?)` inserts a reference after the current selection without removing selected text. An omitted label uses the lowest available positive integer. A new definition is appended and focused for editing; an existing label inserts another reference to its definition. Reference insertion and definition creation form one undo step.

`navigateFootnote('definition' | 'reference')` moves between the current footnote reference and its definition, returning whether a destination was found. **Alt+Enter** visits the definition; **Alt+Shift+Enter** returns to its first reference.

`editReferenceDefinition(label, destination, title?)` updates the shared link definition and returns whether it exists. The destination follows the rules in [Formatting and keys](#formatting-and-keys). Omitted title retains the current title. `format('link', { destination })` edits that shared definition when the caret or selection is in a reference link.

These operations retain the existing document, generation and composition checks. Footnote and definition editing are disabled in TXT and Markdown source modes. Hosts continue to import only the public facade.

## Highlights, callouts and comments

`format('highlight')` toggles the highlight mark; `CaretState.marks` reports `highlight`. Hosts can bind the `highlight` keymap name through `setKeymap`. Formatting is disabled in TXT and Markdown source modes.

Supported callouts render editable bodies, plain titles and optional fold buttons. Enter and Space toggle the focused fold button. Folding retains authored source and does not dirty the document. See the [syntax matrix](supported-syntax.md) for the bounded types and variants.

`setCommentsVisible(boolean)` reveals or hides author comments. Comments start hidden. This changes presentation without changing revision, history or dirty state. While comments are hidden, an edit made from a caret never removes a hidden comment: an edit that would is refused with a `preservation` error. The caret rests inside a hidden comment only in a note with no visible text, and text written there goes into a new paragraph after the comment. A selection that is deleted or replaced removes the hidden comments inside it. Table commands that remove a row, column or table remove the comments in it. [Supported syntax](supported-syntax.md#comments) describes the editing rules. Snapshots and `ClipboardOutput.markdown` retain comments; ordinary text, HTML, inert clipboard metadata and printing exclude them even when revealed. A selection inside a comment copies its selected body with comment delimiters only in explicit Markdown.

## Images

The optional `ImageAdapter` provides:

- `presentation(reference)`: a host-controlled display URL or an unavailable result.
- `importImage({ bytes, mimeType, filename?, source? }, context)`: stores captured bytes and returns a reference. `source` associates bytes with an HTML image URL when available.
- `exportImage(reference, context)`: returns bytes and MIME type for portable clipboard output.

A paragraph that holds only one image behaves as its own block. Text can't be placed on its line: typing, Enter, paste or composition beside it writes a new paragraph before or after it, and typing, Enter or composition with it selected writes one after it. Paste with the image selected replaces it. Arrow keys select the image on the way past it, and Backspace or Delete next to it selects it before deleting it. A click beside the image puts the caret after it. `insertImages()` inserts one block per image and leaves the caret after the last one; see [Inserting images](#inserting-images) for tables and for code and other source. An image that shares its paragraph with text, is linked, emphasised, strong, struck through or highlighted, or sits in a table cell or at the start of a list item, stays inline in its paragraph; with a file adapter, its card displays on its own line. Each form keeps its authored Markdown.

The operation context contains document ID, generation and operation ID. Validate it in native callbacks. Alt text, title and the existing `alt|width` convention remain editor metadata. The adapter owns storage, access control and networking. InkKit contains no Marfa types or storage-path assumptions.

Keep imported bytes available while the captured operation is pending and after insertion, including before the host saves its document. Retention and orphan cleanup belong to the host; a sweep based only on saved Markdown can miss an in-flight import or an unsaved edit. Reject stale callbacks without inserting their references into a replacement document.

The `events.error` callback reports failures that no call is waiting for; see [Errors](#errors). Hosts with native clipboards use `events.clipboard` to receive ordinary image and diagram selections as portable clipboard output. Return a promise that resolves only after the native clipboard write succeeds; reject it on failure. Image and diagram Cut await this acknowledgement before removing source content. Encode byte arrays explicitly when crossing a WebKit JSON bridge.

### Inserting images

`insertImages(images: ImageInsertion[], at?: ClientPoint, expectedGeneration?)` puts the images where the selection is, or at the drop point `at`. Each `ImageInsertion` is `{ reference, alt, title? }`, where `reference` is what the host's adapter stored the image under. It never splits a block that can't be split or discards a selection it can't replace. As with any formatted edit, a result that can't be preserved is refused, and the call throws `preservation`.

The reference is written as the image's Markdown destination, so it's read like a URL. With a file adapter, everything after the first `#` is the fragment, not part of `FileReference.target`. Write a `#` that belongs to a file name as `%23`, such as `Scans/My%23Notes.png`; InkKit doesn't decode it.

- **Paragraph, heading, list item, quote, callout or footnote:** inserts one image block per image, replacing a selection and splitting the paragraph around a caret. The caret ends after the last image.
- **Table cell:** a cell holds one line and no blocks, so the images go inline in the cell, in order and on one line, replacing a selection inside the cell. Alt text and titles are collapsed to one line. The images sit next to each other with no space between them. The caret ends after the last image, the rest of the table keeps its authored spelling, and one undo removes all the images.
- **Code, comments and other source kept as written:** a code block, Mermaid diagram, author comment, front matter, or an unsupported literal block such as a paragraph or table that contains inline HTML, can't hold an image. The images go after the block where the selection ends, inside its list item or quote when it sits in one, and the block and the selection are left as they are. A selection that spans table cells, selects cells, or runs from outside a table into a cell puts the images after the table, and no cell changes; one that runs from a cell out of the table puts them after the block where it ends.
- **Drop point:** with `at`, images are always placed as blocks, after the top-level block at that point or in place of an empty paragraph at or beside it, the same placement as dropped HTML, so a point over a table puts them below the table. The selection isn't checked.

Inserting images needs an image adapter or a file adapter, because either one shows and exports the inserted reference. `insertImages` returns `true` when it inserted the images. It returns `false`, and changes nothing, for an empty list, in source or TXT mode, or with neither adapter; `commandState().commands.insertImages` is `false` in the same cases, and while the editor can't be changed.

## Table refinements

`table('moveRowUp' | 'moveRowDown' | 'moveColumnLeft' | 'moveColumnRight')` moves the selected contiguous rows or columns one position. A caret chooses its cell's row or column. The header remains the first row and cannot be moved into the body; moving a column includes its header and alignment. Selection follows the moved cells. Boundary movements return `false`. Complete cell nodes, including formatting, references, comments and images, travel together. Unsupported literal tables are not reordered.

`table('sortRows', { column?, order?, comparison? })` explicitly sorts all body rows. `column` is zero-based and defaults to the active column; `order` defaults to `ascending`, with `descending` also supported. `comparison` defaults to `text`: case-sensitive UTF-16 code-unit comparison of complete readable clipboard text, including surrounding whitespace. Author comments are excluded; images contribute alt text and footnote references contribute `[label]`. Number comparison trims surrounding whitespace and accepts finite decimal numbers, including signs, fractions and exponents; when the column holds any other nonblank value, the call returns `false` without changing the table. A `column` outside the table, or an option that does not belong to the command, throws `invalid-argument`. Empty and whitespace-only cells always come last, and equal keys retain their authored order. The header and column alignments remain fixed; selection follows the original top-left row and retains the selected columns within that row.

Ordinary paste accepts rectangular tab-separated spreadsheet text and supported simple HTML tables. Inside a table it begins at the selection's top-left cell, replaces the selected rectangle and clears selected cells not covered by the incoming rectangle. It grows the table to the right and bottom as needed. Outside a table it inserts a new table using the first incoming row as the header. Explicit Markdown, plain-text paste and image imports retain their existing paths. Each movement, sort and spreadsheet paste is one isolated undo operation. See [supported syntax](supported-syntax.md) for input limits and safe fallback.

## Source editing and history

`editingMode` returns `formatted` or `source`. Markdown loads in formatted mode; TXT is always literal source. `setEditingMode(mode, expectedGeneration?)` switches the current Markdown document without changing its identity, generation, revision or dirty state. Leaving source mode takes the source edited there into the formatted document; see below for what that does to history. It returns `false` when unchanged or when formatted mode is requested for TXT. Hosts own the mode control.

`replaceSource(text, expectedGeneration?)` replaces the complete current source as one isolated undo operation, returning `false` for identical source. It accepts unsupported syntax, incomplete Markdown and TXT literally. Snapshots retain the actual complete source, including Markdown spelling changes that render identically. Source input retains unchanged line endings and uses the document’s existing line ending for inserted lines. Switching to formatted editing does not save or canonicalise the source.

`undo(expectedGeneration?)` and `redo(expectedGeneration?)` use the formatted document's history, except for source edits made in source mode that have not yet been taken into the formatted document, which they step through on the text (see below). Each returns whether it applied a history operation. Revisions advance for actual edits and history operations; dirty state compares exact current source with the loaded source. Loading another document resets history. Composition, pending imports, stale generations and destruction retain the existing guards.

Source edits do not parse the document. Typing, paste, cut, replacement, `replaceSource` and any other change made while in source mode take effect on the text at once: `snapshot()`, the `changed` event, the revision and the textarea all use it. Each is an undo step on the text: a pause of more than 500 ms in typing ends a step, and an edit that is not typing is a step of its own that later typing does not join. The last 100 steps are kept. `clipboardSnapshot()` and `printableSnapshot()` read the text and leave history alone.

The formatted document takes the source in when you leave source mode, which costs as much as loading the document. All the source steps then become one step of the formatted history: after switching to formatted mode, `undo()` reverts everything edited in source mode since it was entered (or since the last switch), not one step at a time. Redo does not survive leaving source mode either: steps undone in source mode are dropped on the switch, because taking the source in commits a new formatted step. Loading another document discards the steps.

Source-mode typing and paste edit source literally; an explicitly supplied clipboard `markdown` takes precedence over plain text. Ordinary whole-document copy and printing retain the existing semantic Markdown exports. A source selection exports its exact selected substring as `ClipboardOutput.markdown`, without unselected definitions. Ordinary text/HTML interprets that selection as a standalone Markdown fragment: complete constructs are semantic, while incomplete and unsupported constructs remain literal. Intersections with complete author comments in the whole document are excluded even when only a comment body is selected. Code and TXT stay literal.

## Find and replacement

`find(text, expectedGeneration?)` selects the next match and wraps at the end. `replace(search, replacement, expectedGeneration?)` replaces the matching selection, or the next wrapped match, and selects the inserted text. It returns whether text changed. `replaceAll(search, replacement, expectedGeneration?)` applies non-overlapping matches from the original document once and returns the number changed. Empty search and identical replacements do not create history entries.

Search is literal and case-insensitive using JavaScript Unicode matching. No regular expressions, Unicode normalisation or replacement macros are interpreted; `$&`, `$1` and backslashes remain replacement text. Source and TXT search their full literal text, including line endings and syntax. Formatted matching searches editable text, code and preserved literal content within a single text segment, including author-comment bodies. It does not cross non-text nodes or structural boundaries, or search link destinations, reference identifiers and other attributes. Use source editing to search that source syntax.

Formatted replacements retain surrounding structure and formatting; replacement text inherits the first matched text’s formatting when a match spans differently formatted text. Newlines become hard breaks in ordinary formatted content and remain literal in code/source/TXT. Unsupported reconstruction, including multiline table cells, rejects with `preservation` before mutation. Each replacement or replace-all is one isolated undo operation. Selection-only find and navigation do not change revision or dirty state. Replacement obeys the same composition, pending-operation and generation guards as other edits.

## Headings and navigation

`headings(expectedGeneration?)` returns immutable, ordered `Heading` entries with `id`, `level`, readable `text`, `documentId`, `generation` and `revision`. The opaque ID belongs to the current loaded document and editing mode. Heading-looking code, unsupported literal blocks and TXT do not create outline entries. Author comments are excluded from heading text; image alt text and readable footnote labels are retained. Query again after edits, undo, document loads or mode changes.

`navigateHeading(entry)` validates the entry against the current document, generation, revision, editing mode and load epoch. A stale entry throws `stale-document`; a value that is not a heading entry throws `invalid-argument`. Navigation focuses and scrolls to the heading and reveals folded callout ancestors without changing source, history, revision or dirty state. Hosts own outline layout and presentation; the playground demonstrates selection and navigation through these APIs.

Blocks that browsers would otherwise expose as unnamed, generic elements carry a role that allows a name. An attachment card is a `group` named after the file, so its Open, status and Retry controls read as part of it. A footnote definition is a `note` named by `footnote` and its label, as its reference is. An author comment, shown when comments are revealed, is a `note` named by `comment`. A preserved Markdown block is a `group` named by `preservedMarkdown`. The roles are not configurable; the names are. Copied HTML omits these roles and names.

`EditorOptions.keymap` and `setKeymap(bindings: Keymap)` configure bindings in ProseMirror key notation. `Keymap` maps each `ShortcutName` to an array of keys. `setKeymap` replaces the whole map: a name it leaves out loses its binding, or returns to its default. A formatting name runs the `format` command of the same name. Formatting names are `heading1`, `heading2`, `heading3`, `heading4`, `heading5`, `heading6`, `paragraph`, `bold`, `italic`, `strikethrough`, `highlight`, `code`, `codeBlock`, `quote`, `bulletList`, `orderedList` and `taskList`. Formatting has no default host bindings.

A name that is not listed here throws `invalid-argument`. History names are `undo` and `redo`. Table names are `tableInsert`, `tableAddRowBefore`, `tableAddRowAfter`, `tableAddColumnBefore`, `tableAddColumnAfter`, `tableDeleteRow`, `tableDeleteColumn`, `tableDeleteTable`, `tableAlignLeft`, `tableAlignCenter`, `tableAlignRight`, `tableMoveRowUp`, `tableMoveRowDown`, `tableMoveColumnLeft`, `tableMoveColumnRight`, `tableSortRows` and `tableExit`.

Omitted history bindings keep `Mod-z` for undo and `Mod-y` / `Shift-Mod-z` for redo; an explicit empty array disables configurable defaults for that name. Omitted `tableExit` bindings keep `Mod-Enter` and `Enter` in table context; an explicit empty array disables both. Unbound default history keys are consumed to prevent the browser's separate undo stack from changing source/TXT. The same history bindings apply across formatted/source/TXT surfaces. Formatted and table commands are disabled outside their applicable context and while read-only. Keyboard dispatch follows the same mutation guards as facade calls. Hosts can query command availability to present current shortcut/menu state.

## Opening links

A primary click with Mod held opens a link, in formatted mode, whether or not the editor is editable. Mod is Command on Apple platforms and Control elsewhere: the same key as `Mod` in [keymap](#appearance-labels-and-shortcuts) notation, detected from `navigator.platform` in the same way. On a Mac, Control-click keeps opening the context menu. A click without Mod places the caret as usual. No click on a link, with or without Mod, Shift or the middle button, makes the web view follow it, including in read-only mode, and Mod-click on a link doesn't select the link or its paragraph.

- **Markdown link:** InkKit calls `events.openLink(href)` with the link's destination. It doesn't call `openLink` when the rendered address is empty. That includes `[text]()` and any address that isn't relative, a fragment, a query, or an `http`, `https`, `mailto` or `tel` address, such as `javascript:`, `ftp:`, `file:` or an app-specific scheme. The editor renders those links without an address, and copies them as their text; it's the same list that HTML import and print use. The Markdown source keeps the address as authored. Relative addresses and fragments, such as `notes/a.md` or `#intro`, reach the host as they are, not resolved against the page's address.
- **Wiki link:** InkKit calls `WikiLinkAdapter.open`. See [Optional wiki links and files](#optional-wiki-links-and-files).

While Mod is held and the pointer is over the editor root, InkKit's stylesheet shows the pointer cursor over each link that opens. InkKit tracks the key itself, including while focus is in a host control, so hosts don't need key listeners or classes for it. Opening a Markdown link from the keyboard isn't supported yet.

## Optional wiki links and files

Linked syntax and controlled file views require 0.0.10 or later. `EditorOptions.wikiLinks` and `EditorOptions.files` are independent optional adapters. Omitting both retains the existing simple editor and `ImageAdapter` contract. See [supported syntax](supported-syntax.md#linked-syntax) for the bounded grammar and representation table.

`WikiLinkAdapter.open(reference, context)` receives a `WikiLinkReference` with decoded `target`, optional `fragment` and authored readable `label`. Optional synchronous `resolve(reference, context)` returns `{ missing?: boolean }` for presentation. It does not supply an editor URL. The host owns lookup, permissions and navigation; use source mode to edit the authored target or alias. A primary click with Mod (see [Opening links](#opening-links)) or Enter or Space on the focused link invokes `open`, including in read-only mode. No note index, backlink graph or transclusion is created.

`FileAdapter` provides:

- `resolve(reference, context): Promise<FilePresentation>`: resolves an opaque `FileReference`, described below. The host identifies the actual file kind; InkKit does not infer it from an extension.
- Optional `exportImage(reference, context): Promise<PortableImage>`: supplies portable image bytes for copy and print. If omitted, a configured legacy `ImageAdapter` can export path images. Named images require this callback for portable image output. Image import remains with `ImageAdapter.importImage`; no file storage/import API is added.
- Optional `open(reference, context)` and `contextMenu(reference, point, context)`: target the authored reference for host actions. `point` is a `ClientPoint`, `{ clientX, clientY }` in CSS pixels of the web view's client area. The host owns permissions, Open/Reveal UI and error handling for asynchronous native actions.

A `FileReference` has these fields:

- `kind`: `path` for `![alt](destination)` and `wiki` for `![[name]]`.
- `reference`: the whole reference, including any fragment. For `path`, it's the Markdown destination, `a/b.mp4#t=10`. For `wiki`, it's `target#fragment`, or `target` when there is no fragment.
- `target`: the reference without its fragment. Use it to find the file.
- `fragment`: optional. Everything after the separating `#`, such as `t=10` or `page=3`. When it's absent, `target` equals `reference`.
- `label`: optional. The alt text of a path image without its width, or `target#fragment` for a named file.
- `width`: optional. The authored width, from `|400` in the alt text or the name.

| Markdown                           | `kind` | `reference`             | `target`         | `fragment`    |
| ---------------------------------- | ------ | ----------------------- | ---------------- | ------------- |
| `![](a/b.mp4#t=10)`                | `path` | `a/b.mp4#t=10`          | `a/b.mp4`        | `t=10`        |
| `![](a.pdf?x=1#page=2#more)`       | `path` | `a.pdf?x=1#page=2#more` | `a.pdf?x=1`      | `page=2#more` |
| `![](My%23Notes.pdf)`              | `path` | `My%23Notes.pdf`        | `My%23Notes.pdf` | absent        |
| `![[My file.pdf#page=3]]`          | `wiki` | `My file.pdf#page=3`    | `My file.pdf`    | `page=3`      |
| `![[ My file.pdf # page=3 \|200]]` | `wiki` | `My file.pdf#page=3`    | `My file.pdf`    | `page=3`      |
| `![[My\#Notes.pdf#page=2]]`        | `wiki` | `My#Notes.pdf#page=2`   | `My#Notes.pdf`   | `page=2`      |

In a path, the fragment starts at the first `#`, so a `#` that belongs to a file name must be written `%23`, as in any URL. InkKit doesn't decode it: the target of `My%23Notes.pdf` is `My%23Notes.pdf`. A backslash escape doesn't keep a `#` in a path's name, because Markdown removes it before InkKit reads the destination: the target of `![](My\#Notes.pdf)` is `My`. InkKit gives `?` no meaning, so a query stays in `target`. In a named file, a `#` in the name is escaped as `\#`, and `target` holds the name with the escape removed, so don't find the target by splitting `reference` at its first `#`. Named targets and fragments are trimmed; internal spaces are kept.

`FileContext` extends `DocumentContext` with an `AbortSignal`. The `FilePresentation` union accepts `image`, `audio`, `video` or `pdf` with a private `url`, optional `label` and matching optional `mimeType`; `file` with an optional label; `missing`; or `error` with a message. Missing/error results can carry a useful label. Unknown kinds, executable URL schemes and mismatched data-URL/MIME kinds are rejected. Resource URLs must serve the declared kind and be usable in the host's offline web view. The adapter owns their lifetime, byte validation, access checks and fragment mapping, including media `#t=` or PDF `#page=`. InkKit retains those authored fragments without interpreting storage paths or creating a network fallback.

Resolution never changes authored Markdown or revision. Each view captures document identity and an internal reload epoch. Retry, reference replacement, source mode, folded ancestors, reloads and destruction abort obsolete work; late results are ignored even when the host ignores the signal. Width/label changes use current editor metadata without changing reference identity. The Retry button starts a new request. Missing, rejected, undecodable and unsupported presentations retain source and expose a descriptive card. A rejected or invalid resolution, a preview that fails to load, and an exception from `FileAdapter.open`, `FileAdapter.contextMenu`, `WikiLinkAdapter.resolve` or `WikiLinkAdapter.open` are reported through `events.error` as `file-unavailable`, with the original error as `cause`. Use source mode to edit or remove a reference.

Images share the existing width convention and resize handle. A completed gesture creates one isolated undo entry; cancelled gestures do not change source. Read-only, composition and pending edits reject resizing. Audio/video use native controls with no autoplay, retaining playback through read-only transitions and adjacent edits. Hiding or destroying their view pauses playback and releases the element's resource. Returning to the formatted view resolves again without autoplay. PDF uses a sandboxed frame and an always-visible descriptive host Open card. Preview is best effort: sandbox restrictions can block a built-in PDF viewer without firing an error event. The card remains available when the frame is blank; PDF content is not executed. File cards never execute their content.

`clipboardSnapshot()` and `printableSnapshot()` resolve kinds afresh from frozen content, independently of current display elements. Source edits, reloads (including identical generations), mode changes and destruction cancel pending exports and reject stale output. Non-image kinds use the descriptive fallbacks in the syntax table. `PrintableWarning.code` distinguishes `attachment-fallback` from `attachment-unavailable`; existing `diagram-unavailable` remains unchanged. A resolved image's missing or invalid portable bytes reject print with `image-unavailable`; clipboard retains its description and `images.error`. Private display URLs are never exported. Native copy/cut should use `events.clipboard` and acknowledge a successful clipboard write before source removal.

## Lightweight presentation from 0.0.11

`EditorOptions.rendering` accepts `codeHighlighting?: boolean` and `diagramPreview?: boolean`. Both default to `true`. Set either to `false` at mount to skip that presentation plugin. Code and diagram source remain editable and retain their authored spelling; mode changes, history and portable output keep the same contracts. Explicit clipboard and printable diagram exports still render on demand, including when previews are disabled. Mermaid loads after source validation on the first actual render; its queue/cache is shared across instances. An offline single-file bundle built from the main entry still includes the rendering code, so disabling previews reduces execution work rather than bytes. To leave Mermaid out of the bundle, use the core entry described in [Builds without diagrams](#builds-without-diagrams). Code highlighting leaves a code block longer than 5,000 characters plain, and once highlighting in one load or edit has taken 200 ms, the blocks it has not reached stay plain until they are edited. The text of these blocks is still editable and is saved unchanged. See [measured baselines](performance.md).

Buffered `insertText()` supports multiline text and normalises CRLF/CR to LF in formatted insertion, including code blocks. In ordinary blocks it inherits the active marks and inserts semantic breaks in one history transaction. Source/TXT retain their existing literal insertion rules.

Buffered `insertText()` inserts exactly the text it's given and changes nothing outside it, in one history step. Markdown input rules apply at most as if the last character had been typed after the rest: `**x**` becomes strong `x`, and `*x* ` stays literal because its last character is a space. Backspace straight afterwards undoes the rule, as it does after typing. Text the browser inserts in one piece, such as dictation or a text replacement, follows the same rule.

Formatted plain-text insertion preflights source preservation before dispatch. Multiline table-cell text that cannot reopen under the supported table dialect rejects with `preservation`, retaining source, revision, selection and history. This also applies to buffered multiline input; a success never means that an unsaveable document was accepted.

## Builds without diagrams

The package has two entry points with the same exports:

- `@aicayzer/inkkit` renders diagrams with Mermaid.
- `@aicayzer/inkkit/core` never imports Mermaid. Mermaid is still installed as a dependency, but a host that imports only this entry does not bundle it, so each web view parses and holds a much smaller page. See [measurements](performance.md#builds-with-and-without-mermaid-october-14-2026).

With the core entry, `mermaid` fences remain editable code blocks that keep their authored source. No preview is shown, whatever `rendering.diagramPreview` says, and `events.error` never reports `diagram-unavailable`, while editing or when copying. Clipboard output and `printableSnapshot()` keep the diagram source as readable code, the same fallback as a diagram that cannot render: clipboard `diagrams` entries carry an `error`, and print reports a `diagram-unavailable` warning.

Import from one entry throughout the app. If any module imports `@aicayzer/inkkit`, the bundle includes Mermaid and every editor renders diagrams. The stylesheet import, `@aicayzer/inkkit/style.css`, is the same for both entries.

```ts
import { InkKitEditor } from '@aicayzer/inkkit/core'
import '@aicayzer/inkkit/style.css'
```
