# Inkkit 0.1.4

Typing and paste fixes for links and addresses. No API changes.

- Typing a complete wiki link, such as `[[Note]]`, makes it a link when the host enables `wikiLinks`. Before, it was saved as escaped text. Text that was already escaped in a note stays text, including after an IME composition is cancelled.
- Typing an angle autolink, such as `<https://example.com>`, saves it as typed. Text typed after it stays outside the link, and code or bold typed around it keeps its own formatting. `<xs:element>` becomes a link, as CommonMark reads it; text such as `<div>` stays literal.
- Typing `<` and `>` around an address that is already in the note saves an angle autolink. Before, the `>` was refused.
- Plain-text paste of an address wrapped in formatting characters, such as ` **http://example.com**`, is no longer refused.
- Typing `|` into an address in a table cell saves an explicit link with the pipe escaped. Before, the edit was refused.
- An address typed inside backticks stays code and isn't linked. An address ends at its first backtick, so a pasted `` `http://example.com` `` links to the address without the backtick.
- The README shows how Inkkit keeps Markdown as written.

Behavior changes: text typed at the end of a loaded angle autolink now lands outside it, and an address ends at its first backtick. In a block where an edit changes a link's form, another bare address in that block can be written in angle brackets.

Compatibility review: 0.1.4 fixes behavior without adding, removing or renaming API, so a patch version is appropriate. Existing calls need no migration. The native boundary is unchanged, so the native WebKit evidence from 0.1.3 still applies.
