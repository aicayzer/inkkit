# Inkkit 0.7.11

This patch release moves the actions on a code block and a file card into icons in a corner, and lets a host add its own actions to a file card. The new field is additive: a host that sets none sees the changes below and no other.

**A file card's actions are icon buttons in its corner.** Open is now an arrow icon with no text at the end of the card's first row. Before, the name and the arrow were one link. Now the name is plain text. The button keeps its accessible name and tooltip, the `fileOpen` label followed by the card's name, and it still calls `FileAdapter.open`, also in a read-only editor. A card with `activation: 'card'` is unchanged: the whole card is the one Open control.

**A host can add actions to a file card.** A `file` presentation takes a new optional `actions` field, a list of [`FileCardAction`](https://inkkit.cyzr.me/reference/adapters#filecardaction):

- `label` is the button's accessible name and tooltip, used as given.
- `icon` is an image drawn as a mask in the button's text color, such as a data URL of an SVG. A URL that loads from the network or runs script is refused, as it is for a wiki link icon.
- `run(reference, context)` is called when the person activates the button. A thrown exception reports `file-unavailable`.

The host's buttons come before Open. A placeholder, and a card with `activation: 'card'`, take no actions: a presentation that gives them is invalid.

**Both sets of icons wait until they are needed.** A card's icons show while the pointer is over the card or focus is inside it. The code block's Copy icon shows while the pointer is over the block, the selection is inside it, or a control of the block has focus. The language button is unchanged and always shown. The hidden icons stay in the tab order, so Tab reaches them and shows them. A device with no hover shows them always.

The concepts page for code blocks said that the language and Copy buttons appear together. It now says what Inkkit draws.

See [the adapters reference](https://inkkit.cyzr.me/reference/adapters#filecardaction).

Hosts update the package and rebuild their offline page. A host that styled the name link of a file card through Inkkit's internal classes needs to look again, because the name is no longer inside a button. The unchanged `InkKitRTF` Swift package resolves from the same release tag.
