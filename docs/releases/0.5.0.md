# Inkkit 0.5.0

Hosts can opt into local diagnostic recording to investigate intermittent editor failures without recording writing. `setDiagnosticsEnabled(true)` starts a bounded trace of input kinds, composition and focus transitions, editor state, operations and classified refusals. `diagnosticReport()` returns that trace independently of document snapshots, including when a preservation check refuses an edit.

The recorder retains the first substantive failure and a short recovery sequence. Reports omit document text, HTML, clipboard content, authored destinations, host document identifiers and arbitrary exception messages. Font and geometry information is measured only when a report is requested. Disabling diagnostics clears retained history and removes observation listeners.

The host owns the opt-in setting, local persistence and explicit report export. Inkkit adds no network or storage dependency. Recording is disabled by default and does not change editing, saving or undo behavior.

This release adds public diagnostic methods and report types for [#436](https://github.com/aicayzer/inkkit/issues/436). It does not claim to fix the unreproduced code-block preservation rejection, system prediction rendering or the separate WebKit caret-height limitation. The existing preservation guard remains in place.

Hosts update the package, rebuild their offline page and regenerate license notices. The unchanged `InkKitRTF` Swift package resolves from the same release tag.
