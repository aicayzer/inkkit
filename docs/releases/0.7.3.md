# Inkkit 0.7.3

This patch release changes how loaded pictures and file cards look and keeps code block controls in view. It adds no API.

**A picture that loads is drawn bare.** It has rounded corners and no border, padding or caption row. Its name is the hover title on the element and stays its accessible name. A picture that is loading or has failed keeps its card. A loaded picture no longer has an Open button, so hosts offer Open through `FileAdapter.contextMenu`, which is unchanged. The resize handle now overlaps the picture's right edge at rest. See [the adapters reference](https://inkkit.cyzr.me/reference/adapters).

**A file card's name and open arrow are one link.** Hovering anywhere on it underlines the name and highlights the arrow, and a click anywhere on it opens the file. It is one focusable control labelled `Open <name>`. `.inkkit-file-open` now wraps the name and the arrow. `activation: 'card'` is unchanged.

**Code block controls stay visible.** The language control and the Copy button no longer hide when a block is neither hovered nor focused.

Hosts update the package, rebuild their offline page and regenerate license notices. The unchanged `InkKitRTF` Swift package resolves from the same release tag.
