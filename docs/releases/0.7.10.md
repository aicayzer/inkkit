# Inkkit 0.7.10

This patch release makes the diagnostic report hold far more editing history. It is additive: the report keeps `schemaVersion: 1`, and the only new field, `count`, is optional.

**Diagnostics no longer fill with the editor's own calls.** Each keystroke or selection change used to record several `operation` events for calls Inkkit made to itself, such as keeping the selection in view and, for a host that sets `commandStateChanged`, publishing command state. Those calls are no longer recorded, so input, focus and selection events stay in the ring much longer. Calls a host makes, and calls a person makes through a shortcut or a link, are still recorded.

**A synchronous call that succeeds records one event.** It records only its `success` event instead of a `begin` and `success` pair. A call that returns a promise still records `begin` when it starts and then its outcome, so a call that never settles stays visible. A refused call still records `begin` and `refused`, and a call that records other events while it runs keeps its `begin`, so those events stay between its `begin` and its outcome.

**Consecutive repeats share one event.** An event that matches the previous one in every field and in its state increases that event's `count` instead of adding an entry. `sequence` and `elapsedMs` describe the latest occurrence, so the event covers sequences `sequence - count + 1` through `sequence`. Events that freeze an incident are never merged, and an incident's tail stops changing once it holds 40 entries.

A host that counts events should add each event's `count`, which is absent for a single occurrence. See [`DiagnosticEvent`](https://inkkit.cyzr.me/reference/editor#diagnosticevent).

Hosts update the package and rebuild their offline page. The unchanged `InkKitRTF` Swift package resolves from the same release tag.
