# Inkkit 0.7.13

This patch release lets you type a space after a bare URL at the end of a line. It changes no public API.

**A space typed after a bare URL before a soft line break is saved.** Before, the edit was refused with `preservation` and the keystroke did nothing. Markdown drops a space at the end of a line, so Inkkit saves it as `&#x20;`, and a bare URL would take that reference into its address. Now the URL is saved in a form that ends before the space:

- A URL is saved in angle brackets: `See <https://example.com>&#x20;`. Once the space is no longer the last character on its line, the URL is saved bare again.
- A `www.` address is saved as `[www.example.com](http://www.example.com)`. An email address stays bare.
- The same applies when a deletion leaves the space there, in list items and quotes, and after punctuation that ends the address, such as `https://example.com.`.
- Typing a space after a character reference that follows an address, such as the `&amp;` in `https://example.com&amp;`, keeps the link's target.
- Formatting around the URL keeps its delimiters: a space typed in `**https://example.com  ` and a line ending saves `**https://example.com \` and the line ending.

**A space typed before a break written as two trailing spaces is saved.** Markdown would read the typed space as part of the break, so the edit was refused for any text, not only after a URL. The break is now saved as a backslash and a line ending once a space or tab comes before it, which is how Shift+Enter writes a break. A break written after an encoded space, such as `&#x20;  `, keeps its spelling.

**Line breaks that other Markdown apps read are kept.** Inkkit reads spaces and tabs that hold a tab before a line ending as a soft break, but CommonMark and GFM readers, such as GitHub, read two final spaces as a hard break. When you type a space before such spaces, they now stay after the typed space, which is saved as `&#x20;`, so each reader keeps the break it showed before. Other spaces and tabs before a line ending are still replaced by the encoded space.

An unedited document still saves byte for byte, and blocks an edit doesn't reach keep their bytes. See [Markdown support](https://inkkit.cyzr.me/concepts/markdown).

Hosts update the package and rebuild their offline page. The unchanged `InkKitRTF` Swift package resolves from the same release tag.
