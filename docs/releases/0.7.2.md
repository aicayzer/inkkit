# Inkkit 0.7.2

This patch release fixes how the caret and the selection look under a loose line height, reads wiki links as Marfa does, and refines code block controls. It adds one rendering option.

**The caret and the selection sit on the text.** Under a loose line height, WebKit draws the caret and the selection from the bottom of the previous line's text, so on every wrapped line the caret was a full line tall and started above the text, and the highlight sat above it too ([WebKit bug 287429](https://bugs.webkit.org/show_bug.cgi?id=287429)). In formatted mode Inkkit now draws both itself: the caret at the height of the text on every line, following the line you chose at a soft wrap, and the selection as one bar per line, centred on its text, behind it. The web view's caret stays in place, transparent, so accessibility tools and input methods still read its position, and it returns during composition, for range, image and block selections, in empty blocks, in read-only or unfocused editors, and in source and TXT modes. Drawing runs where a fine pointer is the primary input; touch devices keep the system caret and handles. Set the new `rendering.drawnSelection` to `false` to keep the web view's caret and highlight. See [the caret](https://inkkit.cyzr.me/guides/appearance#the-caret) and [style the selection](https://inkkit.cyzr.me/guides/appearance#style-the-selection).

**Wiki links read as Marfa reads them.** A link runs from the last `[[` before its `]]` on the same line, so an unclosed `[[` no longer turns its whole paragraph into source and hides the other links in it. `[` characters pair from the start of a run, a lone `[` or `]` is part of the name, the alias is everything after the first `|` that comes before a `#`, and the heading runs from a `#` before any `|` to the next `|`. Newly read: `[[a]b]]`, `[[a[b]]`, `[[[b]]`, `[[a|b|c]]`, `[[a|b]c]]`, `[[a#b#c]]`, `[[a#]]` and `[[a|]]`. A paragraph where a `[` touches a link's opening brackets, as in `[[[[c]]`, stays exact source. A `suggest` name ending in `]` is refused, because it would close the link early. Saved bytes are unchanged for unedited notes. See [wiki links and file embeds](https://inkkit.cyzr.me/concepts/markdown#wiki-links-and-file-embeds).

**Code block controls.** The language and Copy controls appear together on hover, with focus in the block or on a control, and while the language menu is open, and stay at the visible right edge as the code scrolls. The language menu has a search row and a line-wrap toggle; wrapping is per block and changes neither the source nor the history. Code blocks and tables use 10px corners in the base stylesheet and every preset.

Hosts update the package, rebuild their offline page and regenerate license notices. The unchanged `InkKitRTF` Swift package resolves from the same release tag.
