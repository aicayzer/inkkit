{/* @api InkKitEditor */}
`InkKitEditor` is the editor facade. You create it with `InkKitEditor.mount`, load a document, and read it back with `snapshot`. Options and events are in [Options and events](/reference/options), adapter interfaces in [Adapters](/reference/adapters), and every error code in [Errors](/reference/errors).

## Upgrading from 0.3

Version 0.4 adds RTF documents. A host that offers only Markdown and TXT keeps its behavior, and most code compiles unchanged, because `InkKitEditor`, `EditorOptions`, `EditorEvents`, `DocumentInput` and `DocumentSnapshot` take the offered formats as a type argument that defaults to `TextDocumentFormat`. Check these:

- **`DocumentFormat` includes `'rtf'`.** A text load whose format variable is typed `DocumentFormat` no longer compiles, because an RTF load has a `document` instead of `text`. Type it `TextDocumentFormat`.
- **A `Record<DocumentFormat, …>` needs an `rtf` key.** For example, a map of file extensions or menu titles by format.
- **Four format commands are added:** `alignLeft`, `alignCenter`, `alignRight` and `alignJustify`. `FormatCommand`, `ShortcutName` and `CommandState.commands.format` include them; they are always `false` outside RTF. Code that lists every command, or a toolbar built from the record's keys, sees them.
- **`InkKitEditor<F>` is generic.** `mount` with `formats` that include `'rtf'` returns an `InkKitEditor<'md' | 'rtf'>`, say, whose snapshots and `changed` events can be RTF; narrow on `format`. A helper that accepts any editor takes `InkKitEditor<DocumentFormat>`, since an editor typed with text formats only doesn't accept RTF loads.

## Conventions

These rules apply to every member:

- **Synchronous members throw and asynchronous members reject**, always with an [`InkKitError`](/reference/errors#inkkiterror). `mount`, `printableSnapshot`, `clipboardSnapshot`, `paste` and `destroy` return promises and never throw. Every other member returns its result at once.
- **A failed call changes nothing.** The document, selection, revision and undo history are as they were, and no `changed` or `commandStateChanged` event is sent for it. The exception is `internal`, after which the editor's state can't be trusted. See [how errors arrive](/reference/errors#how-errors-arrive).
- **Events from a call arrive before it returns.** When a synchronous call succeeds, its `changed` and `commandStateChanged` events are sent in order immediately before it returns. An asynchronous call sends the events it raises after its first pause as they happen. If your handler makes a call that sends a newer event of the same kind, the older ones still waiting are dropped.
- **`null` counts as omitted** for an optional parameter or option field, because WebKit bridges send JSON `null` for a missing value. `snapshot(null)` reads the current generation.
- **Unknown names fail.** An option, event handler, label, shortcut name, command or options field that this reference doesn't list throws `invalid-argument`, so a misspelling is never ignored. The input values `TextDocumentInput`, `TextRange` and `Heading` are checked only for the fields they need. An RTF `document` is checked completely, and an unknown field in it throws `invalid-argument`.
- **Pass the expected generation.** Most members that read or change the document take `expectedGeneration` as their last parameter. When the loaded document has another generation, the call throws `stale-document` and changes nothing. Omitted means the current generation. A host that calls Inkkit across a native bridge should pass it on every call. See [documents and saving](/concepts/documents).
- **Offsets are UTF-16 code units** in the text of the snapshot that names them, and `to` is exclusive. Row and column indices are zero-based.
- **Points and rectangles are CSS pixels** in the web view's client area, the coordinates of DOM pointer events. They aren't device pixels and aren't relative to the root.
- **`false` means the call didn't apply here**, such as a formatting command in source mode, and nothing changed.

See [preservation](/concepts/preservation).

| ---------------------------- | ------------------------------------------------------------------------------------ |
| `@aicayzer/inkkit`           | `InkKitEditor`, `InkKitError` and every type, with Pele previews for Mermaid syntax. |

```ts
import '@aicayzer/inkkit/style.css'
```

## Local diagnostics

{/* @api InkKitEditor.setDiagnosticsEnabled */}

### setDiagnosticsEnabled

`setDiagnosticsEnabled(enabled: boolean): void`

Enables content-free local tracing, which is off by default. Enabling starts a new random session. Disabling removes diagnostic listeners and clears retained events and the incident. It accepts only a boolean and throws `invalid-argument` otherwise. It works before loading, while composing, while an import is pending, and in a read-only editor. Like other members, it throws `destroyed` after destruction.

{/* @api InkKitEditor.diagnosticReport */}

### diagnosticReport

`diagnosticReport(): DiagnosticReport`

Returns a detached [diagnostic report](#diagnosticreport) without saving or parsing the document. It works even when `snapshot()` refuses because of composition, a pending import or preservation. Requesting a report never changes the document, selection, revision or history. It throws `destroyed` after destruction.

Reports stay local. Inkkit does not store them on disk or send them anywhere. The host decides whether to export a report and supplies package and application versions separately. No document text, HTML, clipboard content, input data, printable keys, link addresses, file paths, document identifiers, error messages or cause strings are recorded. Font family names are bounded declarations from the host's CSS, not a measurement of the font used for each rendered glyph.

{/* @api DiagnosticReport */}

### DiagnosticReport

The version-one report contains `schemaVersion: 1`, `enabled`, a random `sessionId`, current `state`, and up to 200 `events`. The first preservation or internal failure freezes an `incident` with `triggerSequence` and up to 200 preceding events including that event. Its `tail` retains the first 40 subsequent events. Expected guard refusals, such as composition and stale generations, remain in the live events without occupying the incident. Later editing cannot overwrite the frozen incident. Toggle diagnostics off and on to start another capture. Reports are independent copies, so changing a returned object cannot change retained history.

While enabled, `presentation` is measured only when requesting a report. If layout cannot be measured it is omitted. Disabled reports have empty events, no incident and no presentation; current numeric counters and guard state remain available. If the view state cannot be read, the report uses its last observed safe state, or initial unloaded state before any observation. Tracing is best effort and cannot interrupt an edit or replace its original error.

{/* @api DiagnosticEvent */}

### DiagnosticEvent

Each event has a monotonically increasing `sequence`, integer `elapsedMs` since enabling, a `kind` and safe editor `state`. Kinds are `input`, `composition`, `focus`, `selection`, `operation`, `preservation`, `error` and `enabled`. Optional `phase` describes transitions or operation begin, success and refusal. `input` groups browser input into text, composition, delete, paste, drop, history, format or other. Raw browser input strings are never retained.

Optional `operation` groups calls into snapshot, edit, history, load, configuration, output, selection, lifecycle or other. `code` is an existing `EditorErrorCode`. Preservation `path` is unchanged, local, regions or whole. A safe `reason` is matching-budget, source-location, reopen-mismatch, parse-refusal or unexpected. Diagnostic tracing does not enable the internal preservation cross-check, retain source comparisons or change edit validation.

{/* @api DiagnosticState */}

### DiagnosticState

Current guard state records `ready`, `editable`, `composing` and `pending`, with numeric `revision` and optional `generation`, the document `format`, and `mode`. Optional `selection` contains numeric `from` and `to`. Formatted offsets are ProseMirror document positions; literal offsets are UTF-16 positions in the source surface. Document identifiers and selection text are excluded.

{/* @api DiagnosticPresentation */}

### DiagnosticPresentation

The selected block's declared `fontFamily` is capped at 160 characters and permits only letters, numbers, spaces, commas, quotes, underscores and hyphens. `fontSize` and optional `lineHeight` are numeric CSS pixels. `fontWeight` is numeric, and `fontStyle` is normal, italic, oblique or other. Optional `headingLevel` is one through six for a heading. A normal line height is omitted. `block` is paragraph, heading, code, literal or other. `marks` contains at most 12 known mark names, with unknown names replaced by other. Mark attributes are excluded.

`caretColor` is a bounded CSS colour or other. Optional `caret` contains left, top, right and bottom coordinates for the formatted selection. `viewport` contains the window width and height, and `scroll` contains left and top offsets of the configured scrolling container. Numeric presentation values are finite and bounded to ten million CSS pixels. The report reads configuration and geometry; it does not move the caret, focus the editor or change input preferences.

## Lifecycle

{/* @api InkKitEditor.mount */}

### mount

`static mount(root: HTMLElement, events: EditorEvents, options?: EditorOptions): Promise<InkKitEditor>`

`static mount<F extends DocumentFormat>(root: HTMLElement, events: EditorEvents<F>, options: EditorOptions<F> & { formats: readonly F[] }): Promise<InkKitEditor<F>>`

The editor's type argument `F` is the formats it offers. Without `formats`, or with only `'md'` and `'txt'`, it is `TextDocumentFormat`, and snapshots are text. With `formats: ['md', 'rtf']`, `F` is `'md' | 'rtf'`, so [`snapshot`](#snapshot) returns either kind and you narrow on `format`. A helper that accepts any editor takes `InkKitEditor<DocumentFormat>`.

Builds the editor inside `root` and adds the class `inkkit-root` to it. The editor has no document until you call [`loadDocument`](#loaddocument). Keep the root in the page, and leave its children alone, until `destroy` completes.

`mount` rejects with `invalid-argument` when `root` isn't an `HTMLElement`, when `events` has no `changed` function or names something that isn't an event, or when `options` has an unknown field or a field of the wrong type. See [`EditorEvents`](/reference/options#events) and [`EditorOptions`](/reference/options#editor-options).

{/* @api InkKitEditor.destroy */}

### destroy

`destroy(): Promise<void>`

Cancels pending work, releases the editor and removes `inkkit-root` from the root if Inkkit added it. Pending `clipboardSnapshot`, `printableSnapshot` and `paste` calls reject with `destroyed`. It resolves when the editor is gone and never rejects. Afterwards every member except `destroy` throws `destroyed`, and calling `destroy` again does nothing. Await it before you remove the root from the page.

## Documents

{/* @api DocumentFormat */}
`DocumentFormat` is `'md'` for Markdown, `'txt'` for literal text or `'rtf'` for rich text. TXT has no formatted mode, and RTF has no source mode. An editor loads only the formats you offer in [`formats`](/reference/options#formats). See [documents and saving](/concepts/documents) for load and version rules, and [rich text](/concepts/rich-text) for what an RTF document holds.

{/* @api TextDocumentFormat */}
`TextDocumentFormat` is `'md' | 'txt'`, the formats whose document is text. It is the default type argument of `InkKitEditor`, `EditorOptions`, `EditorEvents`, `DocumentInput` and `DocumentSnapshot`, so an editor you mount without `rtf` in `formats` takes and returns text documents.

{/* @api FormatPromise */}
`FormatPromise` states what saving a format keeps. Markdown and TXT are `'exact'`, and RTF is `'structure'`. See [what each format promises](/concepts/documents#formats-and-what-they-promise).

| Value         | Meaning                                                                                                            |
| ------------- | ------------------------------------------------------------------------------------------------------------------ |
| `'exact'`     | Saves your file exactly: an unedited document saves the bytes it loaded, and an edit changes only what it touched. |
| `'structure'` | Keeps the structure and marks, and replaces fonts, colors and sizes with Inkkit's style.                           |
| `'lossy'`     | A conversion that drops something, and says what it drops.                                                         |

{/* @api OfferedFormat */}
An `OfferedFormat` is one entry of [`formats`](#formats): a format you offered, with what saving it promises.

{/* @api-scope OfferedFormat */}

| Field     | Type             | Meaning                                      |
| --------- | ---------------- | -------------------------------------------- |
| `format`  | `DocumentFormat` | The format you offered at mount.             |
| `promise` | `FormatPromise`  | What saving a document in this format keeps. |

{/* @api InkKitEditor.formats */}

### formats

`readonly formats: readonly OfferedFormat[]`

The formats you offered in the [`formats`](/reference/options#formats) option, in your order, each with its `promise`. Without the option, the list is Markdown and then TXT; RTF is offered only when you list it. The list is frozen and fixed at mount, so a host can read it once to fill an Open or Save As menu. It works before the first load.

{/* @api DocumentVersion */}
A `DocumentVersion` identifies one revision within a loaded document. Outputs and command state carry these fields.

{/* @api-scope DocumentVersion */}

| Field        | Type     | Meaning                                                   |
| ------------ | -------- | --------------------------------------------------------- |
| `documentId` | `string` | The host's document identity. Inkkit never interprets it. |
| `generation` | `number` | The host-assigned integer identifying the current load.   |
| `revision`   | `number` | The content revision within this load, starting at zero.  |

{/* @api DocumentInput */}
A `DocumentInput` supplies the complete document and its identity for a load or reload. It is a `TextDocumentInput` for Markdown and TXT, or a `RichTextDocumentInput` for RTF. Its type argument is the formats the editor offers, and without `rtf` it is always a `TextDocumentInput`.

{/* @api TextDocumentInput */}
A `TextDocumentInput` loads a Markdown or TXT document from its text.

{/* @api-scope TextDocumentInput */}

| Field        | Type                 | Meaning                                                                            |
| ------------ | -------------------- | ---------------------------------------------------------------------------------- |
| `documentId` | `string`             | The host's document identity, preserved in later snapshots.                        |
| `generation` | `number`             | An integer greater than the loaded generation; the first load accepts any integer. |
| `format`     | `TextDocumentFormat` | The document format, one of those in [`formats`](#formats).                        |
| `text`       | `string`             | The complete authored text. An empty string loads an empty document.               |

{/* @api RichTextDocumentInput */}
A `RichTextDocumentInput` loads an RTF document from the `RichTextDocument` your converter read from the file. It has no `text`.

{/* @api-scope RichTextDocumentInput */}

| Field        | Type               | Meaning                                                                            |
| ------------ | ------------------ | ---------------------------------------------------------------------------------- |
| `documentId` | `string`           | The host's document identity, preserved in later snapshots.                        |
| `generation` | `number`           | An integer greater than the loaded generation; the first load accepts any integer. |
| `format`     | `'rtf'`            | RTF, which must be in [`formats`](#formats).                                       |
| `document`   | `RichTextDocument` | The document to load. Inkkit checks it and puts it in canonical form.              |

{/* @api InkKitEditor.loadDocument */}

### loadDocument

`loadDocument(input: DocumentInput<F>): void`

Replaces the document. The generation must be greater than the loaded one; the first load accepts any integer. A generation that isn't greater, or a format that isn't in [`formats`](#formats), throws `invalid-argument`. An RTF `document` that isn't a valid [`RichTextDocument`](#rich-text-documents), a Markdown or TXT load that has a `document`, and an RTF load that has a `text`, also throw `invalid-argument`; the message names the first problem's path, such as `input.document.blocks[2].content[0].text`. Markdown that can't be kept even as literal source throws `preservation`. Either way the load changes nothing.

A load clears the undo history, returns to formatted mode, cancels pending imports and exports, and sends one `commandStateChanged` and no `changed`. [Load a document](/concepts/documents#load-a-document) lists everything it resets.

{/* @api InkKitEditor.reloadDocument */}

### reloadDocument

`reloadDocument(input: DocumentInput<F>, expectedGeneration?: number): void`

Replaces the document with a newer version of it, under the same generation rule and errors as `loadDocument`. It keeps the selection where it still fits, the focus, the scroll position and, for Markdown, the editing mode, and clears the undo history. See [Reload a changed document](/concepts/documents#reload-a-changed-document).

With `expectedGeneration`, the loaded document must be that generation, or the call throws `stale-document` and changes nothing. That check comes before the generation rule.

{/* @api InkKitEditor.snapshot */}

### snapshot

`snapshot(expectedGeneration?: number): DocumentSnapshot<F>`

Returns the complete current document, which is what a host saves. For Markdown and TXT, the `text` is the exact source, including line endings; an unedited document returns the bytes that were loaded. In source mode it includes what was typed there. For RTF, the `document` is the canonical form of the current document, a new object on each call, which you pass to your converter to write the file.

{/* @api DocumentSnapshot */}
A `DocumentSnapshot` is a `TextDocumentSnapshot` for Markdown and TXT, or a `RichTextDocumentSnapshot` for RTF. Its type argument is the formats the editor offers, and without `rtf` it is always a `TextDocumentSnapshot`. Narrow on `format` before you read `text` or `document`.

{/* @api TextDocumentSnapshot */}
A `TextDocumentSnapshot` combines the fields of `TextDocumentInput` with `DocumentVersion`, plus its saved-state flag.

{/* @api-scope TextDocumentSnapshot */}

| Field   | Type      | Meaning                                                          |
| ------- | --------- | ---------------------------------------------------------------- |
| `dirty` | `boolean` | Whether the current text differs from the text of the last load. |

{/* @api RichTextDocumentSnapshot */}
A `RichTextDocumentSnapshot` combines the fields of `RichTextDocumentInput` with `DocumentVersion`, plus its saved-state flag. Its `document` is always in canonical form.

{/* @api-scope RichTextDocumentSnapshot */}

| Field   | Type      | Meaning                                                                                                                           |
| ------- | --------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `dirty` | `boolean` | Whether the canonical current document differs from the canonical form of the last load. Undoing every edit makes it clean again. |

It throws `preservation` when the current content can't be written as Markdown that reopens as shown, or as an RTF document. A failed snapshot is not an unchanged document: don't save, and keep the document open. See [the save rules](/concepts/documents).

{/* @api InkKitEditor.convertDocument */}

### convertDocument

`convertDocument(format: DocumentFormat, expectedGeneration?: number): ConvertedDocument`

Converts the loaded document to `format`, which must be in [`formats`](#formats), and returns the result with what the conversion lost. It changes nothing in the editor: load the result as a new generation when the person confirms, for example after a Save As to another format.

- **Markdown to RTF** reads the formatted document, including what was typed in source mode. Headings become bold paragraphs and code blocks become paragraphs in code; the [loss codes](#convertdocument) list everything else.
- **RTF to Markdown** writes the document with Inkkit's Markdown writer. Underline, superscript and subscript become `<u>`, `<sup>` and `<sub>`, and a line break in a table cell becomes `<br />`. Alignment is the only loss. Inkkit reads the Markdown back, and if it wouldn't give the same document less its alignment, the call throws `preservation` rather than return a conversion that loses something unreported.
- **The same format** returns a copy with no losses.

Any other pair, such as TXT to or from RTF, throws `invalid-argument`: your converter's plain-text helpers convert TXT, and Markdown and TXT share their text. It has the same state checks as `snapshot`.

{/* @api ConvertedDocument */}
A `ConvertedDocument` is `{ format, text, lost }` for Markdown and TXT, or `{ format: 'rtf', document, lost }` for RTF. `lost` is a frozen list of [`FormatLoss`](#convertdocument) entries in the order of [`FormatLossCode`](#convertdocument); an empty list means the conversion kept everything.

{/* @api FormatLoss */}
A `FormatLoss` names one kind of content a conversion couldn't keep.

{/* @api-scope FormatLoss */}

| Field   | Type             | Meaning                                                     |
| ------- | ---------------- | ----------------------------------------------------------- |
| `code`  | `FormatLossCode` | What was lost.                                              |
| `count` | `number`         | How many places in the document lost it, at least one each. |

{/* @api FormatLossCode */}
`FormatLossCode` is the closed list of what a conversion can lose. A new code is added only in a minor release.

| Code                  | Direction     | What happened                                                                                                                              |
| --------------------- | ------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| `'heading'`           | Markdown, RTF | A heading became a bold paragraph.                                                                                                         |
| `'code-block'`        | Markdown, RTF | A code block became one paragraph in code for each line.                                                                                   |
| `'diagram'`           | Markdown, RTF | A diagram became its source, as paragraphs in code.                                                                                        |
| `'quote'`             | Markdown, RTF | A quote gave up its paragraphs.                                                                                                            |
| `'callout'`           | Markdown, RTF | A callout gave up its title, as a bold paragraph, and its paragraphs.                                                                      |
| `'task'`              | Markdown, RTF | A task item became a plain list item, without its checkbox.                                                                                |
| `'rule'`              | Markdown, RTF | A horizontal rule was left out.                                                                                                            |
| `'footnote'`          | Markdown, RTF | A footnote reference became its label in brackets, and a footnote's text a paragraph that starts with its label.                           |
| `'comment'`           | Markdown, RTF | An author comment was left out.                                                                                                            |
| `'highlight'`         | Markdown, RTF | Highlighted text kept its text without the highlight.                                                                                      |
| `'image'`             | Markdown, RTF | An image was left out.                                                                                                                     |
| `'file'`              | Markdown, RTF | A file embed was left out.                                                                                                                 |
| `'wiki-link'`         | Markdown, RTF | A wiki link became its text.                                                                                                               |
| `'literal'`           | Markdown, RTF | Markdown kept as authored, or raw HTML, became its source as text.                                                                         |
| `'link'`              | Markdown, RTF | A link with an empty address, or one with a control character, became its text.                                                            |
| `'table-alignment'`   | Markdown, RTF | A table lost its column alignment.                                                                                                         |
| `'list-start'`        | Markdown, RTF | A numbered list that started below 1 starts at 1, and one above 2,147,483,647 starts at 2,147,483,647.                                     |
| `'list-item-blocks'`  | Markdown, RTF | A list item's further paragraphs, code or table became lines of its first paragraph, since an RTF item holds one.                          |
| `'list-depth'`        | Markdown, RTF | Lists deeper than 9 levels became lines of the item at the ninth level.                                                                    |
| `'link-underline'`    | Markdown, RTF | Underlined link text lost its underline, which RTF draws on every link.                                                                    |
| `'invalid-character'` | Markdown, RTF | A character RTF can't hold as text, U+0000, U+FFFC or a lone surrogate, became U+FFFD.                                                     |
| `'alignment'`         | RTF, Markdown | A centered, right-aligned or justified paragraph became left-aligned.                                                                      |
| `'mark-spaces'`       | RTF, Markdown | Spaces at the edge of an underlined, struck-through or linked run moved outside it, since Markdown can't start or end a mark with a space. |
| `'empty-line'`        | RTF, Markdown | A paragraph of only a line break became an empty paragraph, or an empty paragraph at the end was left out.                                 |

## Rich text documents

These types describe the JSON form of an RTF document, which your converter reads from and writes to the file. They match the `RichTextDocument` of the `InkKitRTF` Swift package exactly; see [host RTF documents](/guides/web-view#host-rtf-documents).

{/* @api RichTextDocument */}
A `RichTextDocument` is a whole RTF document.

{/* @api-scope RichTextDocument */}

| Field     | Type              | Meaning                                                |
| --------- | ----------------- | ------------------------------------------------------ |
| `version` | `1`               | The model version. 1 is the only version.              |
| `blocks`  | `RichTextBlock[]` | The document's paragraphs, lists and tables, in order. |

{/* @api RichTextBlock */}
A `RichTextBlock` is one of three blocks, told apart by `type`:

- `{ type: 'paragraph', align?, content }`: a paragraph of `RichTextInline` content. `align` is `'center'`, `'right'` or `'justify'`, and absent for left alignment.
- `{ type: 'list', ordered, start?, items }`: a bulleted or numbered list of `RichTextListItem`s. `start` is a numbered list's first number, from 1 to 2,147,483,647, the largest that RTF writes and reads back, and absent for 1. Lists nest up to 9 levels.
- `{ type: 'table', rows }`: a table of rows of `RichTextTableCell`s. It has at least one row and one cell, every row has the same number of cells, and it can't be inside a list.

{/* @api RichTextListItem */}
A `RichTextListItem` is one list item.

{/* @api-scope RichTextListItem */}

| Field    | Type              | Meaning                                                      |
| -------- | ----------------- | ------------------------------------------------------------ |
| `blocks` | `RichTextBlock[]` | One paragraph, then any nested lists. It holds nothing else. |

{/* @api RichTextTableCell */}
A `RichTextTableCell` is one table cell.

{/* @api-scope RichTextTableCell */}

| Field     | Type               | Meaning                                                  |
| --------- | ------------------ | -------------------------------------------------------- |
| `content` | `RichTextInline[]` | The cell's text and line breaks, as one line of content. |

{/* @api RichTextInline */}
A `RichTextInline` is `{ type: 'text', text, marks? }`, a run of text, or `{ type: 'break' }`, a line break inside a paragraph or cell. A run is never empty and never holds `\n`, `\r`, U+000B, U+000C, U+0085, U+2028, U+2029, U+FFFC or U+0000, or a lone surrogate. An edit that would leave one in the text is refused.

{/* @api RichTextMark */}
A `RichTextMark` is `{ type }` for `'bold'`, `'italic'`, `'underline'`, `'strikethrough'`, `'superscript'`, `'subscript'` and `'code'`, or `{ type: 'link', href }` for a link. A run has each type at most once, never both superscript and subscript, and a link's `href` is never empty and has no control character. Any other address is kept as given, such as `http://[`; links that a person adds or pastes must also pass link safety.

**Canonical form.** Inkkit's snapshots, and your converter's output, are canonical: marks are in the order above, a run with a link has no underline, adjacent runs with equal marks are merged, runs are in Unicode Normalization Form C, and `align` and `start` are left out for left alignment and 1. A load accepts a document that isn't canonical and puts it in canonical form; that alone doesn't make it dirty.

## Editability and input

{/* @api InkKitEditor.editable InkKitEditor.setEditable */}

### editable and setEditable

`get editable(): boolean`

`setEditable(editable: boolean): void`

`editable` is whether the person can edit. `setEditable` turns editing on or off for the formatted surface and the source and TXT surface, and sends `commandStateChanged`. It throws `composition` during text composition. It keeps focus, selection, source, revision, dirty state and history.

Every member that changes the document throws `read-only` while editing is off, including `undo` and `redo`. The formatted textbox exposes `aria-readonly="true"`; the source and TXT textarea has its native `readonly` attribute. Enabling editing removes those read-only states. [Read-only mode](/concepts/documents#read-only-mode) lists what stays available.

{/* @api InkKitEditor.setHostActive */}

### setHostActive

`setHostActive(active: boolean | null): void`

Sets the native host's activation state for selection presentation. Pass `true` when the host window is active and the web view holds native input, and `false` when either stops being true. Pass `null` to restore automatic browser focus detection, the default. DOM focus still chooses which editor on the page is active.

The method changes only the active or inactive selection color. It does not focus or blur a surface, collapse a selection, change editing permission, emit a document change, or add history. It works before loading and during composition. Invalid values throw `invalid-argument`; a destroyed editor throws `destroyed`.

{/* @api InkKitEditor.setTextInputPreferences */}

### setTextInputPreferences

`setTextInputPreferences(preferences: TextInputPreferences): void`

Replaces the input preferences on both surfaces. A field you leave out goes back to its default. It throws `composition` during text composition and is a presentation change, not an edit. See [`TextInputPreferences`](/reference/options#editor-options).

{/* @api InkKitEditor.setKeymap */}

### setKeymap

`setKeymap(keymap: Keymap): void`

Replaces every shortcut binding. A name you leave out returns to its default, and a `null` entry keeps that name's default. An unknown name, or a value that isn't an array of strings, throws `invalid-argument`. A command that fails from a shortcut reports its error to `events.error`. Formatting has no default bindings. See [shortcuts](/reference/appearance#shortcuts) for every name, its default and key notation.

{/* @api InkKitEditor.commandState */}

### commandState

`commandState(expectedGeneration?: number): CommandState`

Returns what the editor can do now, for enabling toolbar buttons and menu items, without changing anything. Unlike `snapshot`, it works during composition and pending imports, with the affected commands reported as unavailable. `events.commandStateChanged` sends the same value when it changes. The result describes the moment you ask; a later call can still fail. See [`CommandState`](/reference/options#command-state), which also describes `CaretState`, `Mark` and `Block`.

## Formatting

{/* @api InkKitEditor.format */}

### format

`format(command: FormatCommand, options?: FormatOptions, expectedGeneration?: number): boolean`

Applies one formatting command to the selection in formatted mode, focuses the editor, and returns whether the document, or the marks the next typed text takes, changed. It returns `false` in source and TXT modes and when the command has nothing to change.

[Format commands](/reference/options#format-commands) lists what each `FormatCommand` does and the `FormatOptions` it takes. With `link`, a destination that Inkkit wouldn't open or can't save throws `invalid-argument`, and in a reference link the shared definition changes, as [`editReferenceDefinition`](#editreferencedefinition) does. Giving a link the destination it already has returns `false`.

{/* @api InkKitEditor.moveBlock */}

### moveBlock

`moveBlock(direction: BlockMoveDirection, expectedGeneration?: number): boolean`

Moves the block that holds the caret, or every block the selection touches, one place within its list, quote, callout, footnote or note, as one undo step. In a list, the list item moves with any sublist it holds. Returns whether the blocks moved. It returns `false` at the first or last place, in a table and in source and TXT modes. Front matter stays first. A move that can't be saved and reopened as the same document throws `preservation`.

{/* @api BlockMoveDirection */}
`BlockMoveDirection` selects the previous position with `'up'` or the next position with `'down'` in the block's container.

## Tables

{/* @api InkKitEditor.table */}

### table

`table(command: TableCommand, options?: TableOptions, expectedGeneration?: number): boolean`

Runs one table command in formatted mode and returns whether it applied. It returns `false` in source and TXT modes, outside a table for commands that need one, and at a boundary a move can't cross. Each command is one undo step. An option that belongs to another command throws `invalid-argument`.

[Table commands](/reference/options#table-commands) lists what each `TableCommand` does and the `TableOptions` it takes. The table controls Inkkit draws run these same commands; a refused one reports to `events.error`.

## History and modes

{/* @api InkKitEditor.editingMode InkKitEditor.setEditingMode */}

### editingMode and setEditingMode

`get editingMode(): EditingMode`

`setEditingMode(mode: EditingMode, expectedGeneration?: number): boolean`

`EditingMode` is `'formatted'` or `'source'`, which shows the Markdown in a textarea. A TXT document is always `'source'`, and an RTF document always `'formatted'`. Markdown loads in formatted mode.

`setEditingMode` switches the current Markdown document without changing its identity, generation, revision or dirty state, and maps the selection to the matching text. It returns `false` when the mode is already set, and for TXT and RTF. It works in a read-only editor. Switching to source mode throws `preservation` when the formatted document can't be written. Leaving source mode makes everything edited there one step of the formatted history. The host owns the mode control.

{/* @api InkKitEditor.replaceSource */}

### replaceSource

`replaceSource(text: string, expectedGeneration?: number): boolean`

Replaces the complete source as one undo step and returns `false` for identical source. It accepts any text, including unsupported or incomplete Markdown, and the snapshot holds it as given. An RTF document has no source, so the call throws `invalid-argument`.

{/* @api InkKitEditor.undo InkKitEditor.redo */}

### undo and redo

`undo(expectedGeneration?: number): boolean`

`redo(expectedGeneration?: number): boolean`

Each steps through the history and returns whether it applied a step. In source mode they also step through edits made on the text. Loading a document clears the history. Undo and Redo that the browser sends as input events, such as from its Edit menu, run these members.

{/* @api InkKitEditor.discardUndone */}

### discardUndone

`discardUndone(expectedGeneration?: number): boolean`

Drops every step that `undo` took off the history, so that `redo` has nothing to bring back, and returns whether a redo was available. Use it when your host adds content after an undo and must not let a later redo bring back what the person undid. Any edit already does this by landing; `discardUndone` is for a host that cannot rely on an edit doing it, or that wants `commands.redo` to read `false` before one.

The document, selection, revision, saved bytes and undo steps stay exactly as they are, so this is not an edit: no `changed` event is sent and nothing is added to the history. `commandStateChanged` reports `commands.redo` as `false`. In source mode it also drops the typed source steps that were undone. Loading a document already clears the history. It throws as `undo` does: `stale-document`, `composition`, `operation-pending` and `read-only`, and changes nothing when it does.

## Find and navigation

{/* @api InkKitEditor.find */}

### find

`find(text: string, expectedGeneration?: number): boolean`

Selects the next match after the selection, wrapping at the end, and returns whether it found one. Search is literal and case-insensitive. Source and TXT modes search the full text, including syntax; formatted mode searches readable text within one text segment, not hidden comments, link destinations or other attributes. Formatted matches stay highlighted after editing and moving the caret, until another query, `find('')`, or a document load. `replace` and `replaceAll` also set this query. An empty search clears the highlights and finds nothing. It works in a read-only editor and doesn't change the revision. For a host-owned find bar, see [controls](/guides/controls).

**Migration for existing hosts:** Formatted `find`, `replace` and `replaceAll` now leave author comment bodies out of their matches. Earlier versions searched those bodies even though readable snapshots and exported text omit them. Switch to source mode to search or replace comment text. Existing comments remain byte-for-byte unchanged by formatted replacement.

{/* @api InkKitEditor.searchMatches */}

### searchMatches

`searchMatches(text: string, expectedGeneration?: number): readonly TextRange[]`

Returns every non-overlapping match in document order, using the same literal, case-insensitive matching as `find` and `replaceAll`. An empty query returns an empty array. Formatted mode excludes embedded labels, attributes and matches that cross text segments; source and TXT modes search the full source, including syntax. The returned array and its ranges are frozen.

The ranges use readable UTF-16 offsets and the current `snapshotId`, as described under [textSnapshot](#textsnapshot). Source and TXT offsets reflect the textarea's normalized line endings; a match of either half of CRLF selects the displayed line break. Use single-line queries for host find fields. Do not treat these offsets as raw source offsets.

This call works in read-only mode and changes neither selection, focus, highlights, source, revision nor undo history. Use the count for a find bar and `selectTextRange(range, { reveal: true })` to navigate without taking focus from the field. An edit, reload or mode change makes the returned ranges stale; call `searchMatches` again before using them. `find('')` clears highlights separately.

{/* @api InkKitEditor.replace InkKitEditor.replaceAll */}

### replace and replaceAll

`replace(search: string, replacement: string, expectedGeneration?: number): boolean`

`replaceAll(search: string, replacement: string, expectedGeneration?: number): number`

`replace` replaces the selected match, or the next one, selects the inserted text and returns whether text changed. `replaceAll` replaces every non-overlapping match once and returns how many. Each call is one undo step. The replacement is literal: `$&`, `$1` and backslashes stay as typed. In formatted mode a replacement keeps the surrounding formatting, and a newline becomes a line break; in code, source and TXT it stays literal.

{/* @api InkKitEditor.findSession */}

### findSession

`findSession(onChange: (state: FindState) => void): FindSession`

Opens a find session for a host-owned find bar. The session keeps the query and reports the match count and the position of the selected match to `onChange` whenever they change: after its own commands, after every edit, undo, selection change and mode change, and after a load or reload. `onChange` is not called when the state is the same as the last one it received, and it is not called while a composition or an image import makes the editor unable to answer. An exception it throws goes to `reportError`, as the exceptions of `events` handlers do.

The editor has one set of highlights, so open one session per editor. A new document loaded with `loadDocument` clears the query; `reloadDocument` and a mode change keep it and restore its highlights without moving the selection. Destroying the editor closes its sessions.

Navigation uses the matching rules of `searchMatches`, so counts agree with `find` and `replaceAll`. It selects and reveals each match without taking focus from the host's field. This replaces writing the loop over `searchMatches`, `textSnapshot` and `selectTextRange` described in [controls](/guides/controls#build-your-own-find).

{/* @api FindState */}
A `FindState` is the state of a find session at one moment, with the fields of `DocumentVersion`.

{/* @api-scope FindState */}

| Field     | Type     | Meaning                                                                                              |
| --------- | -------- | ---------------------------------------------------------------------------------------------------- |
| `query`   | `string` | The query, or an empty string when there is none.                                                    |
| `current` | `number` | The position, from 1, of the match that the selection covers exactly, or 0 when it isn't on a match. |
| `total`   | `number` | The number of matches, which is 0 for an empty query.                                                |

{/* @api FindSession */}
A `FindSession` is the handle that `findSession` returns. Each command takes `expectedGeneration` as its last parameter, checked as for `find`, and throws like the members it uses: `stale-document`, `composition`, `operation-pending` and, for replacement, `read-only` and `preservation`. A failed command leaves the query, highlights, selection and document as they were. Once `close` has been called, every other member throws `destroyed`.

{/* @api FindSession.state */}
`state(expectedGeneration?: number): FindState` returns the current state without calling `onChange`.

{/* @api FindSession.find */}
`find(query: string, options?: { direction?: 'next' | 'previous' }, expectedGeneration?: number): boolean` sets the query, highlights its matches and selects one, and returns whether there is a match. A query that differs from the session's selects the first match at or after the selection, or the last one before it with `direction: 'previous'`, wrapping when there is none. With the same query, `'next'` and `'previous'` move from the selected match and wrap at the ends, and without a direction a selection on a match stays. An empty query clears the highlights.

{/* @api FindSession.next FindSession.previous */}
`next(expectedGeneration?: number): boolean` and `previous(expectedGeneration?: number): boolean` move to the following or preceding match of the session's query, wrapping at the ends, and return whether there is a match. They return `false` when the query is empty.

{/* @api FindSession.replace */}
`replace(query: string, replacement: string, expectedGeneration?: number): boolean` selects the match as `find` does, replaces it as `replace` does, then selects the match after it and returns whether the text changed. A match that already reads as the replacement is passed over without an edit or an undo step, so repeated calls reach the end of the document.

{/* @api FindSession.replaceAll */}
`replaceAll(query: string, replacement: string, expectedGeneration?: number): number` replaces every match as one undo step and returns how many it replaced.

{/* @api FindSession.clear */}
`clear(expectedGeneration?: number): void` clears the query and the highlights.

{/* @api FindSession.close */}
`close(): void` stops the session, clears the highlights and stops calling `onChange`. Closing twice does nothing.

{/* @api InkKitEditor.headings */}

### headings

`headings(expectedGeneration?: number): readonly Heading[]`

Returns the outline in document order, as frozen entries. TXT, RTF, code and literal blocks give no entries. Query again after an edit, undo, load or mode change.

{/* @api Heading */}
A `Heading` is an immutable outline entry with the fields of `DocumentVersion`. Pass the entry back to `navigateHeading` while its load, revision and mode remain current.

{/* @api-scope Heading */}

| Field   | Type     | Meaning                                                               |
| ------- | -------- | --------------------------------------------------------------------- |
| `id`    | `string` | An opaque identity belonging to this load, revision and editing mode. |
| `level` | `number` | The heading level, from 1 to 6.                                       |
| `text`  | `string` | The readable heading text, without author comments.                   |

{/* @api InkKitEditor.navigateHeading */}

### navigateHeading

`navigateHeading(heading: Heading): boolean`

Moves the caret to the heading, focuses it, scrolls to it and unfolds callouts that hold it. It returns `true`, or throws `stale-document` for an entry from another generation, revision or mode, and `invalid-argument` for a value that isn't a heading entry. It doesn't change the revision.

## Footnotes, references and comments

{/* @api InkKitEditor.insertFootnote */}

### insertFootnote

`insertFootnote(label?: string, expectedGeneration?: number): boolean`

Inserts a footnote reference after the selection and, when the label has no definition, appends one at the end of the document and puts the caret in it. Both are one undo step. An omitted label uses the lowest positive integer that no footnote uses. A label must be 1 to 999 characters with no whitespace, brackets or backslashes, or the call throws `invalid-argument`. It returns `false` in source and TXT modes, and in RTF.

{/* @api InkKitEditor.navigateFootnote */}

### navigateFootnote

`navigateFootnote(target: 'definition' | 'reference', expectedGeneration?: number): boolean`

Moves the caret to the definition, or the first reference, of the footnote at the caret, and returns whether there was one. Alt+Enter and Alt+Shift+Enter do the same. It works in a read-only editor and returns `false` in source and TXT modes.

{/* @api InkKitEditor.editReferenceDefinition */}

### editReferenceDefinition

`editReferenceDefinition(label: string, destination: string, title?: string, expectedGeneration?: number): boolean`

Changes the destination of the shared link definition for `label`, which matches regardless of case and runs of whitespace, so every link that uses it changes. `destination` follows the same rule as a `format('link')` destination. An omitted `title` keeps the current title; a non-empty one replaces it. An empty `title` throws `preservation`. It returns `false` when no definition has the label, and in source and TXT modes.

{/* @api InkKitEditor.setCommentsVisible */}

### setCommentsVisible

`setCommentsVisible(visible: boolean): void`

Shows or hides author comments. Comments start hidden. This is presentation only: the revision, history and dirty state don't change. While comments are hidden, an edit from a caret that would remove one is refused with `preservation`. See [comments](/concepts/markdown#comments).

## Images and paths

{/* @api InkKitEditor.insertImages */}

### insertImages

`insertImages(images: ImageInsertion[], at?: ClientPoint, expectedGeneration?: number): boolean`

Inserts images that an adapter already stored, at the selection, or as blocks at the drop point `at`: in place of an empty paragraph there, or after the top-level block there. It returns `false`, and changes nothing, for an empty list, in source and TXT modes, in RTF, and when neither an `images` nor a `files` adapter is set.

{/* @api ImageInsertion */}
An `ImageInsertion` names an image the host already stored. Inkkit writes the reference into Markdown; the adapter supplies its display and exported bytes.

{/* @api-scope ImageInsertion */}

| Field       | Type                | Meaning                                                            |
| ----------- | ------------------- | ------------------------------------------------------------------ |
| `reference` | `string`            | The authored image reference, written as the Markdown destination. |
| `alt`       | `string`            | The alternative text describing the image.                         |
| `title`     | `string` (optional) | An optional image title. Omitted titles are empty.                 |

`ClientPoint` is `{ clientX, clientY }`, finite CSS pixels. The reference is read like a URL: with a file adapter, everything after the first `#` is the fragment, so write a `#` in a file name as `%23`. In a table cell, the images go inline on one line. In a code block, comment, front matter or literal block, they go after that block. See [adapters](/guides/adapters).

{/* @api InkKitEditor.appendImages */}

### appendImages

`appendImages(images: ImageInsertion[], expectedGeneration?: number): boolean`

Adds images that an adapter already stored as the last blocks of the document, for a host that attaches them while the person is elsewhere, such as a new note's attachments. `ImageInsertion` and the reference rules are as for [`insertImages`](#insertimages).

- **Where:** one paragraph per image at document level, after the last block, whatever it is: a table, list, quote, callout, closed code fence, footnote definition or comment. Nothing before the new blocks changes. An empty document takes the images in place of its one empty paragraph, so it doesn't save a `<br />` ahead of them.
- **What stays:** focus doesn't move, nothing scrolls, and the selection stays on the text it covered. A select-all selection stays a select-all, so it then includes the images.
- **History:** the images are one undo step, apart from the typing before and after them. One `changed` event reports the new text.
- **Returns `false`, and changes nothing,** for an empty list, in source and TXT modes, and when neither an `images` nor a `files` adapter is set. `commandState().commands.appendImages` has the same conditions.
- **`preservation`:** a document that ends in a code fence with no closing fence can't take a block after it and still save as it was, so the call throws `preservation` and changes nothing. Close the fence first, for example with [`replaceSource`](#replacesource).

Throws the checks in the [state table](#state-checks).

{/* @api InkKitEditor.insertPaths */}

### insertPaths

`insertPaths(paths: string[], at: ClientPoint, expectedGeneration?: number): boolean`

Inserts dropped file paths as literal text. In formatted mode each path becomes a paragraph at the drop point: in place of an empty block, or after the top-level block there. In source and TXT modes `at` is ignored and the paths go at the selection, separated by blank lines. It returns `false` only for an empty list.

## Files and wiki links

{/* @api InkKitEditor.refreshReferences */}

### refreshReferences

`refreshReferences(targets?: readonly string[], expectedGeneration?: number): void`

Resolves wiki links and file embeds again, after something they point to changed: a note was created, renamed or deleted, or a file arrived. With no `targets`, every reference resolves again. With `targets`, only those whose `target` equals one of the strings do, compared exactly, with escapes removed as in [`FileReference.target`](/reference/adapters#filereference) and [`WikiLinkReference.target`](/reference/adapters#wikilinkreference). An empty list refreshes nothing, and a name that matches nothing is ignored.

- **Wiki links:** [`WikiLinkAdapter.resolve`](/reference/adapters#wikilinkadapter) runs again for each match, and the link shows its new missing state.
- **File embeds:** [`FileAdapter.resolve`](/reference/adapters#fileadapter) runs again for each match that is on screen. The card stays as it is until the new answer differs from it, so it neither blanks nor moves, and an answer with the same fields leaves it untouched. A card that is still loading starts over. An error card from a rejected resolve stays until the new answer arrives, and a card whose preview failed to load shows its loading state while it tries again. A rejection or an invalid result shows an error card and reports `file-unavailable`, as for any other resolve.
- **Not covered:** images shown only through `ImageAdapter.presentation`, which has no separate resolve step.

It changes no document, revision, history, selection or scroll position, so it also works in a read-only editor, during composition and while an image import is pending. In source and TXT modes there are no references to draw, so it does nothing, and they resolve afresh when formatted mode returns. A result that arrives after a reload, a mode change or `destroy` is ignored.

Throws `invalid-argument` for `targets` that isn't a list of strings, then `not-ready` before a document is loaded, and `stale-document` for a different `expectedGeneration`. See [files and wiki links](/guides/adapters).

## Clipboard and print

These members prepare content for a host that writes the native clipboard or prints. [Copy, paste and print](/concepts/clipboard) describes what each output contains.

{/* @api InkKitEditor.clipboardSnapshot */}

### clipboardSnapshot

`clipboardSnapshot(scope?: ClipboardScope, expectedGeneration?: number): Promise<ClipboardOutput>`

Resolves with clipboard content and the version it was copied from. It rejects with `stale-document` if the document, its revision or the editing mode changes before the output is ready, and with `preservation` when the selection can't be written as Markdown. Resolve it before you touch the native clipboard, and keep the existing clipboard on failure. A missing image or diagram picture is reported in the `error` of its `ClipboardImage` or `ClipboardDiagram` entry, not as a rejection. From an RTF document, the output has no images or diagrams, and `markdown` is the copied content written as Markdown, without alignment: text such as `**literal**` is escaped, so it stays text.

| `images`   | `ClipboardImage[]`   | Image entries in their HTML order, with portable bytes or errors. |
| `diagrams` | `ClipboardDiagram[]` | Each complete Mermaid diagram in the copied scope.                |

{/* @api ClipboardImage */}

{/* @api InkKitEditor.paste */}

### paste

`paste(input: ClipboardInput, expectedGeneration?: number): Promise<void>`

Pastes content that the host read from the native clipboard, through the same import as a paste the person makes. Read the clipboard once; don't read it again while this runs. An unknown field throws `invalid-argument`.

{/* @api ClipboardInput */}
A `ClipboardInput` supplies representations from one clipboard read. Inkkit chooses the applicable representation using the current mode and import rules.

{/* @api-scope ClipboardInput */}

| Field      | Type                         | Meaning                                                                               |
| ---------- | ---------------------------- | ------------------------------------------------------------------------------------- |
| `text`     | `string`                     | The plain text representation, required even when another representation is supplied. |
| `markdown` | `string` (optional)          | Explicit authored Markdown, taking precedence over text and HTML.                     |
| `html`     | `string` (optional)          | The HTML representation, imported only when the current mode permits it.              |
| `images`   | `CapturedImage[]` (optional) | Captured image bytes associated with the HTML image sources or their order.           |

An image item whose `source` equals an image's `src` belongs to that image; items without a `source` fill the rest in order. In Markdown source mode, `paste` inserts `markdown`, or else `text`, literally; in TXT it inserts `text`. In RTF, `markdown` pastes as its text, unparsed; otherwise `html` keeps what RTF holds, and `text` pastes a paragraph for each line. [Rich text](/concepts/rich-text#paste) describes the conversion. The promise resolves once the content is inserted. It rejects with `stale-document` if the document is replaced, or editing is turned off, while images import. An image that the adapter can't import becomes the text `[Name: image unavailable]` and `events.error` receives `image-unavailable`; the paste still resolves. Without `options.images`, a paste that holds an image is refused whole: nothing is inserted and the promise rejects with `image-unsupported`; see [images without an adapter](/reference/adapters#images-without-an-adapter).

{/* @api InkKitEditor.pasteAsPlainText */}

### pasteAsPlainText

`pasteAsPlainText(text: string, expectedGeneration?: number): boolean`

Inserts `text` literally at the selection and returns whether the document changed. It is the one way to paste literal text in formatted mode, and it never makes links or formatting.

{/* @api InkKitEditor.printableSnapshot */}

### printableSnapshot

`printableSnapshot(expectedGeneration?: number): Promise<PrintableDocument>`

Resolves with the whole current document as standalone HTML, whatever the selection, folding and comment visibility. The host owns the Print and PDF commands. The result and its arrays are frozen, and `assets` holds copies of the bytes.

{/* @api PrintableDocument */}
A `PrintableDocument` is the complete frozen print output with `DocumentVersion`. The host chooses when to show the Print or PDF dialog.

{/* @api-scope PrintableDocument */}

| Field      | Type                          | Meaning                                                                |
| ---------- | ----------------------------- | ---------------------------------------------------------------------- |
| `format`   | `DocumentFormat`              | The source document format, Markdown or literal text.                  |
| `html`     | `string`                      | A standalone HTML document with embedded print CSS and data images.    |
| `styles`   | `string`                      | The print stylesheet on its own.                                       |
| `assets`   | `readonly PortableImage[]`    | Copies of the portable image bytes, in HTML order.                     |
| `warnings` | `readonly PrintableWarning[]` | Descriptions of output that degraded without failing the whole export. |

{/* @api PrintableWarning */}
A `PrintableWarning` describes a fallback in otherwise usable print output.

{/* @api-scope PrintableWarning */}

| Field     | Type                                                                         | Meaning                                                                                          |
| --------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| `code`    | `'diagram-unavailable' \| 'attachment-fallback' \| 'attachment-unavailable'` | The fallback category: `diagram-unavailable`, `attachment-fallback` or `attachment-unavailable`. |
| `message` | `string`                                                                     | A readable explanation of the degraded output.                                                   |

It rejects rather than return partial output: with `stale-document` if the document changes while it runs, `image-unavailable` when an authored image has no adapter or its bytes can't be read, and `diagram-unavailable` when a diagram that previewed can't be rasterized. Output that degrades is reported in `warnings`; see [print](/concepts/clipboard#print).

## Readable text and layout

These members let a host build its own find bar, accessibility or overlay UI over the editor's readable text. See [controls](/guides/controls) for the pattern.

{/* @api InkKitEditor.textSnapshot */}

### textSnapshot

`textSnapshot(expectedGeneration?: number): ReadableTextSnapshot`

Returns the readable text and the selection, frozen, with a `snapshotId` that names them. In source and TXT modes the text is the textarea's text, with CRLF as LF. In formatted mode, blocks and line breaks are joined with LF, and author comments and the metadata of reference definitions are left out.

{/* @api ReadableTextSnapshot */}
A `ReadableTextSnapshot` contains readable text and selection together with `DocumentVersion`. It does not replace the exact saved source from `snapshot`.

{/* @api-scope ReadableTextSnapshot */}

| Field        | Type                      | Meaning                                                                                  |
| ------------ | ------------------------- | ---------------------------------------------------------------------------------------- |
| `snapshotId` | `string`                  | An opaque identity local to this editor, changed by document revisions and mode changes. |
| `format`     | `DocumentFormat`          | The source format, Markdown or literal text.                                             |
| `mode`       | `'source' \| 'formatted'` | The editing mode at the time of capture.                                                 |
| `text`       | `string`                  | Readable text with normalised textarea line endings in source and TXT modes.             |
| `selection`  | `TextRange`               | The selected readable range in this same snapshot.                                       |

{/* @api TextRange */}
A `TextRange` addresses a range within one readable snapshot, using zero-based UTF-16 offsets.

{/* @api-scope TextRange */}

| Field        | Type     | Meaning                                                        |
| ------------ | -------- | -------------------------------------------------------------- |
| `snapshotId` | `string` | The identity of the readable snapshot that owns these offsets. |
| `from`       | `number` | The inclusive starting offset in the readable text.            |
| `to`         | `number` | The exclusive ending offset. Equal endpoints describe a caret. |

A load, a reload, a new revision or a mode change makes earlier snapshot IDs stale, and a range that carries one throws `stale-document`. Caret changes, scrolling and resizing don't. A range with an offset outside the text, `to` before `from`, or an offset that splits a surrogate pair throws `invalid-range`.

{/* @api InkKitEditor.selectTextRange */}

### selectTextRange

`selectTextRange(range: TextRange, options?: { focus?: boolean; reveal?: boolean }): void`

Selects the range. `focus` puts focus in the editor and `reveal` scrolls the range into view; both default to `false`, so focus stays in a host search field. A complete image alt text or footnote label selects that node, and a callout title selects the callout. Part of one throws `invalid-range`. It works in a read-only editor.

{/* @api InkKitEditor.revealTextRange */}

### revealTextRange

`revealTextRange(range: TextRange): void`

Scrolls the range into the viewport that [`setViewport`](#setviewport) describes, unfolding a callout that holds it. It works in a read-only editor.

{/* @api InkKitEditor.replaceTextRange */}

### replaceTextRange

`replaceTextRange(range: TextRange, text: string): boolean`

Replaces the range with literal text as one undo step, keeping the surrounding structure and formatting, and returns whether the text changed. In formatted mode the range must sit in one text block. A range that crosses an image, a line break, a hidden comment or a block boundary throws `invalid-range`; use source mode to change syntax.

{/* @api InkKitEditor.textRangesRects */}

### textRangesRects

`textRangesRects(ranges: readonly TextRange[]): readonly (readonly TextRect[])[]`

Measures a batch of ranges and returns one frozen array of rectangles for each, in order. It checks the whole batch before measuring, keeps no cache, and returns an empty array for an empty batch. Hidden content has no rectangles.

{/* @api TextRect */}
A `TextRect` measures content in CSS pixels in the web view's client coordinate space, matching DOM pointer coordinates.

{/* @api-scope TextRect */}

| Field           | Type     | Meaning                                            |
| --------------- | -------- | -------------------------------------------------- |
| `left`, `right` | `number` | The horizontal coordinates of the rectangle edges. |
| `top`, `bottom` | `number` | The vertical coordinates of the rectangle edges.   |
| `width`         | `number` | The horizontal extent in CSS pixels.               |
| `height`        | `number` | The vertical extent in CSS pixels.                 |

{/* @api InkKitEditor.visibleTextRanges */}

### visibleTextRanges

## Native text input

A host whose native layer receives typing or keys before the web view does passes them to Inkkit with these members. Both require the expected generation, so input meant for a replaced document fails instead of landing in the new one. See [embed in a web view](/guides/web-view).

{/* @api InkKitEditor.insertText */}

### insertText

`insertText(text: string, generation: number): boolean`

Inserts exactly `text` at the selection and returns `true`. It returns `false`, and inserts nothing, during text composition. In formatted mode, Markdown input rules apply as if the last character were typed after the rest, so `**x**` becomes bold `x`, and the insertion is one undo step. Text with line breaks is inserted as ordinary text with line breaks, and CRLF and CR become LF. Source and TXT modes insert the text literally.

{/* @api InkKitEditor.keyDown */}

### keyDown

`keyDown(input: KeyInput, expectedGeneration: number): boolean`

Runs a key press through Inkkit's key handling and returns whether Inkkit handled it. When it returns `true`, the host must not also handle the key natively.

{/* @api KeyInput */}
A `KeyInput` describes a native key press using DOM keyboard names and modifier state.

{/* @api-scope KeyInput */}

| Field      | Type                 | Meaning                                                       |
| ---------- | -------------------- | ------------------------------------------------------------- |
| `key`      | `string`             | The KeyboardEvent key value, such as Enter or a typed letter. |
| `code`     | `string` (optional)  | The optional physical-key code, such as KeyB.                 |
| `metaKey`  | `boolean` (optional) | Whether the Meta key is held; omitted means false.            |
| `ctrlKey`  | `boolean` (optional) | Whether the Control key is held; omitted means false.         |
| `altKey`   | `boolean` (optional) | Whether the Alt or Option key is held; omitted means false.   |
| `shiftKey` | `boolean` (optional) | Whether the Shift key is held; omitted means false.           |

It handles the keymap bindings and, in formatted mode, Alt+Enter and Alt+Shift+Enter for footnotes and the editor's own keys such as Enter, Tab and Backspace in lists and tables. Tab and Shift+Tab indent and outdent a list item through the default `indent` and `outdent` bindings. In source and TXT modes it handles Enter, Tab, Backspace and Delete with no Command, Control or Alt held, and returns `false` for other keys. It returns `false` during composition.

In source and TXT modes, Backspace and Delete remove a whole grapheme when the selection is collapsed. Backspace removes the preceding grapheme and Delete removes the following one. If the caret is inside a grapheme, either key removes that whole grapheme. An explicit selection is deleted exactly as selected, even when it contains only part of a grapheme. These deletions use the existing typing history group.

In a read-only editor, a bound key and Enter, Tab, Backspace and Delete throw `read-only`. Tab and Shift+Tab still move between table cells in formatted mode. A block move key, and a key bound to `indent` or `outdent`, returns `false` so the native behaviour applies.

## Focus

{/* @api InkKitEditor.focus InkKitEditor.blur */}

### focus and blur

`focus(expectedGeneration?: number): void`

`blur(expectedGeneration?: number): void`

`focus` puts focus in the surface for the current mode: the formatted editor, or the textarea in source and TXT modes. `blur` takes focus off Inkkit's text surfaces and leaves focus anywhere else, such as in a host control or a button Inkkit draws, where it is. Use it instead of finding Inkkit's elements yourself. Neither checks composition, read-only or pending imports. Loading takes focus off the editor, so call `focus` after a load only when editing should start at once.

{/* @api InkKitEditor.cancelPendingImports */}

## cancelPendingImports

```ts
editor.cancelPendingImports(expectedGeneration?: number): void
```

Cancels the pending image paste or drop without changing editability, document bytes, revision or history. It aborts the adapter's signal and clears `CommandState.pending` immediately. The pending `paste` rejects with `stale-document`; a DOM paste or drop reports that code through `events.error`. Nothing from the cancelled paste is inserted. With no pending import, it does nothing.

Throws `not-ready` before a document is loaded, `stale-document` for a different `expectedGeneration`, or `destroyed` after destruction. It works during composition and in read-only mode. At a save boundary, either wait for the paste or cancel it before taking a fresh snapshot; [saving guidance](/concepts/documents#save-the-document) describes the host's choice.
