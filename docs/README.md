# InkKit documentation

These guides describe InkKit’s public contracts. Published versions and their verification evidence are on the [releases](https://github.com/aicayzer/inkkit/releases) page.

| Guide                                           | Use it to                                                                                                  |
| ----------------------------------------------- | ---------------------------------------------------------------------------------------------------------- |
| [Supported syntax](supported-syntax.md)         | Compare rendered and editable content, literal preservation, adapter requirements and unsupported formats. |
| [Integration and customisation](integration.md) | Start with a simple editor or connect richer host controls and image storage.                              |
| [Host API](api.md)                              | Check exact operations, errors, availability, history and asynchronous contracts.                          |
| [Preservation and clipboard](preservation.md)   | Understand source fidelity, sharing, literal fallback and failed-operation handling.                       |
| [Development playground](playground.md)         | Select fixtures, reset controlled state and inspect facade observations.                                   |
| [Development](development.md)                   | Run bounded package/browser/native checks and follow the GitHub workflow.                                  |
| [Performance](performance.md)                   | Reproduce minimal/rich offline size, startup and editing measurements.                                     |
| [Releases](releasing.md)                        | Verify the actual package and record publication evidence.                                                 |
| [Historical verification](verification.md)      | Read retained evidence for earlier releases.                                                               |

The [Project](https://github.com/users/aicayzer/projects/3) tracks feature issues and review progress; version milestones hold delivery scope and future publication checklists. Planned features belong in those records, not in the supported-syntax table.
