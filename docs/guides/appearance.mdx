Inkkit's styles apply only inside the mounted root, so the rest of your page keeps its own.

## Choose a preset

Try **Theme** and **Appearance** in the [editor playground](/editor). Standard is the playground's default. Changing either control keeps your document and undo history.

| Preset    | Appearance                                                     | Table and code block corners |
| --------- | -------------------------------------------------------------- | ---------------------------- |
| Standard  | Inkkit's familiar colors and a light code surface.             | 8px                          |
| Calm      | Softer colors, including diagram categories at 35% strength.   | 8px                          |
| Essential | Neutral grays, including code highlighting and pie categories. | 4px                          |

Every preset includes light and dark colors, system sans typography at 15px, normal paragraph spacing and a neutral 3px quote rule with rounded ends. They use system fonts already on the device and need no network access.

Import the base stylesheet and the preset you want, then apply its attribute to your own editor root:

```ts
import '@aicayzer/inkkit/style.css'
import '@aicayzer/inkkit/themes/standard.css'
```

```html
<div id="editor" data-inkkit-theme="standard"></div>
```

Use `themes/calm.css` with `data-inkkit-theme="calm"`, or `themes/essential.css` with `data-inkkit-theme="essential"`. The attribute can also go on an ancestor shared by editors that use the same preset. Each stylesheet sets only public tokens under its matching attribute. It does not style the rest of the page.

To offer a switcher, import all three files and change your root's `data-inkkit-theme` value. This changes CSS without remounting the editor or loading the document again. The preset supplies the editor background; your app still owns the page background and controls.

The base stylesheet on its own keeps the existing appearance. It does not automatically apply Standard.

### Customize or copy a preset

Set your own tokens on the same root to override a preset. Preset selectors use `:where()`, so a normal class selector takes precedence:

```css
.document-editor {
  --inkkit-reading-width: 48rem;
  --inkkit-padding-inline: 24px;
  --inkkit-code-radius: 6px;
  --inkkit-quote-rule-color: light-dark(#777777, #aaaaaa);
}
```

For a preset you maintain yourself, copy its CSS from the installed package's `dist/themes/` directory, rename the attribute value and import that file alongside `style.css`. Keep the public tokens and customize their values. A copied file stays under your control when Inkkit updates; compare it with the package preset when you upgrade.

## Set tokens

Import the stylesheet once, then set tokens on the root or any ancestor. Each editor root can have its own values.

```ts
import '@aicayzer/inkkit/style.css'
```

```css
.document-editor {
  --inkkit-font-family: 'Iowan Old Style', serif;
  --inkkit-font-size: 17px;
  --inkkit-reading-width: 48rem;
  --inkkit-padding-inline: 24px;
  --inkkit-accent-color: #286343;
}
```

Use the public `--inkkit-*` tokens; properties beginning `--_inkkit-` are internal. [Tokens](/reference/appearance#tokens) lists the available settings and defaults.

To align your own header with the writing column, set `--inkkit-column-inset` on an ancestor of both.

## Match light and dark mode

By default the editor follows the system setting. Its default colors use CSS `light-dark()` and system colors such as `CanvasText`, so text, menus and code highlighting switch with the scheme.

When your app has its own theme setting, set `--inkkit-color-scheme` to `light` or `dark` with the rest of your theme. The base stylesheet leaves the editor background transparent. Presets set `--inkkit-background-color`; set your page's `color-scheme` and background in the same rule:

```css
:root[data-theme='light'] {
  color-scheme: light;
  --inkkit-color-scheme: light;
}
:root[data-theme='dark'] {
  color-scheme: dark;
  --inkkit-color-scheme: dark;
}
body {
  background: Canvas;
}
```

Your own token values can follow the scheme too, for example `--inkkit-accent-color: light-dark(#286343, #7bc89a)`. Presets use this to switch their colors without a JavaScript theme option. Diagram previews follow the editor's appearance; clipboard and print diagrams keep the light palette for portable output.

## Adjust the focus ring

Inkkit draws one focus ring on its controls, such as file card buttons, table controls, audio and video, and a separate ring on the editing surfaces. Set `--inkkit-focus-width`, `--inkkit-focus-color` and `--inkkit-focus-offset` for the controls, and the `--inkkit-surface-focus-*` tokens for the surfaces, which default to the control values.

To draw no ring around the text while keeping the controls' rings:

```css
.document-editor {
  --inkkit-surface-focus-width: 0;
}
```

Footnote references and wiki links draw their ring outside the text, in the current text color. The Copy and language buttons on code blocks use the control focus tokens too.

## Links

Links and wiki links take `--inkkit-accent-color` and gain an underline on hover. A wiki link that `WikiLinkAdapter.resolve` reports as missing keeps a dashed underline, so people who can't tell its color apart still see it, and it also shows in forced-colors mode. Assistive technology receives the `wikiMissing` label as the link's description. The underline has no token of its own.

## Style the selection

Inkkit paints the selected text itself, so the selection covers the text and not the margins or the gaps between blocks. Two tokens set its color: `--inkkit-selection-background` while the editor has focus in an active window, and `--inkkit-inactive-selection-background` otherwise.

A page has one selection, so only one editor paints it. The editor that last took the selection keeps it painted in the inactive color when focus moves to a host field, when you call [`blur`](/reference/editor#focus-and-blur), and when the window resigns. Selecting text anywhere else on the page, or in another editor, clears it. Source and TXT modes use the browser's own selection, with the same two colors. The painted selection never changes the document, the revision or the saved bytes.

```css
.document-editor {
  --inkkit-selection-background: color-mix(in srgb, gold 45%, transparent);
  --inkkit-inactive-selection-background: color-mix(
    in srgb,
    gray 30%,
    transparent
  );
}
```

## Localize labels

Inkkit draws some text of its own: accessible names for the editing surfaces, the placeholder, table and file card controls, menu items and status messages. Pass `labels` at mount with strings from your localization catalog. Omitted labels keep their English defaults.

```ts
import { InkKitEditor } from '@aicayzer/inkkit'

const editor = await InkKitEditor.mount(root, events, {
  labels: {
    formattedEditor: 'Éditeur Markdown',
    placeholder: 'Commencez à écrire…',
    fileOpen: 'Ouvrir',
    tableAddRow: 'Ajouter une ligne',
  },
})
```

Inkkit inserts labels as text, never as markup. An unknown key makes `mount` reject with `invalid-argument`. Labels are fixed at mount, so to change language, save, `destroy()` the editor and mount a new one. Your toolbar and menu text stay in your app. [Labels](/reference/appearance#labels) lists every key and its default.

## What not to style

Classes and markup inside the editor are not an API. Don't write rules for `.ProseMirror`, `.inkkit-*` classes or the elements inside the root: they can change in any release, and copied and printed output doesn't carry them. Style your own root element for layout, such as its height and scrolling, and use tokens for everything inside it.

A root element with a fixed height or its own scrolling clips the printed page at that height. Let it grow when the page prints, for example `@media print { html, body, #editor { height: auto; overflow: visible } }` for a root element with the id `editor`.

If a change you need has no token, [open an issue](https://github.com/aicayzer/inkkit/issues) rather than overriding an internal selector.

## Accessibility

Inkkit gives the editing surfaces accessible names from `formattedEditor`, `sourceEditor` and `plainTextEditor`. Its controls are buttons that the keyboard reaches, with names from labels. File cards, footnote definitions, author comments and preserved Markdown blocks carry roles and names, and the slash and suggestion menus expose a listbox with the selected option announced.

Task items expose checkboxes that the keyboard can reach and toggle. Read-only editors expose that state to assistive technology. Bind `openLink` in your [keymap](/reference/appearance#shortcuts) so a person can open the link at the caret with the keyboard.

The default colors and presets provide contrast on their own backgrounds. Check text, controls, selection and focus when you customize tokens or place the editor on a different background. Remaining issues are tracked under the [`accessibility` label](https://github.com/aicayzer/inkkit/issues?q=is%3Aissue%20is%3Aopen%20label%3Aaccessibility).
