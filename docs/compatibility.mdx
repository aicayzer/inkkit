Inkkit runs in WebKit and Chromium from the versions below, ships as ES modules only, and has two entries: one that renders Mermaid syntax with Pele and one that leaves the diagram renderer out of your page.

## Browser engines

| Engine                                     | Oldest supported version                    |
| ------------------------------------------ | ------------------------------------------- |
| WebKit: Safari and `WKWebView`             | 17.5, the WebKit in iOS 17.5 and macOS 14.5 |
| Chromium: Chrome, Edge and Android WebView | 123                                         |
| Firefox                                    | 125, untested                               |

These are the oldest versions in which every required API below works, according to MDN browser compatibility data 8.1.5:

| API                                                                                                           | WebKit | Chromium | Firefox | In an older engine                                                                                   |
| ------------------------------------------------------------------------------------------------------------- | ------ | -------- | ------- | ---------------------------------------------------------------------------------------------------- |
| [`Intl.Segmenter`](https://developer.mozilla.org/docs/Web/JavaScript/Reference/Global_Objects/Intl/Segmenter) | 14.1   | 87       | 125     | The editor doesn't load.                                                                             |
| Regular expression lookbehind assertions                                                                      | 16.4   | 62       | 78      | The editor doesn't load.                                                                             |
| ES2022 class static blocks                                                                                    | 16.4   | 94       | 93      | The editor doesn't load.                                                                             |
| CSS [`light-dark()`](https://developer.mozilla.org/docs/Web/CSS/color_value/light-dark)                       | 17.5   | 123      | 120     | Code text takes the editor text color until you set the `--inkkit-code-*` tokens.                    |
| CSS [`color-mix()`](https://developer.mozilla.org/docs/Web/CSS/color_value/color-mix)                         | 16.2   | 111      | 113     | Muted text, rules, code backgrounds and the selection lose their default colors.                     |
| CSS [`:has()`](https://developer.mozilla.org/docs/Web/CSS/:has)                                               | 15.4   | 105      | 121     | A small image preview isn't widened to its minimum size.                                             |
| CSS [`lh` unit](https://developer.mozilla.org/docs/Web/CSS/length#lh)                                         | 16.4   | 109      | 120     | Task checkboxes aren't centered on the first line of their item.                                     |
| [CSS Custom Highlight API](https://developer.mozilla.org/docs/Web/API/CSS_Custom_Highlight_API)               | 17.2   | 105      | 149     | Optional. The engine draws its own selection, which also fills the margins beside the selected text. |

Inkkit uses the Custom Highlight API only when the engine supports both `CSS.highlights` and `::highlight()` styling. Firefox has the first from 140 and the second from 149.

### What is tested

Changes to editor code, dependencies and workflows run the browser test suite in Playwright's Chromium on Linux and Playwright's WebKit on macOS, and opens pages built from the packed package in both. Documentation-only changes use formatting and site checks instead. These are the current Playwright builds, not the oldest supported versions. Firefox isn't tested. Playwright's WebKit is not `WKWebView`, so test your app's own web view on the systems you support.

## Page requirements

Declare UTF-8 in the page that loads Inkkit, for example with `<meta charset="utf-8">`. Without it, WebKit can read a single-file page as Latin-1 and the script doesn't load; see [Embed in a web view](/guides/web-view#build-a-single-offline-page).

## Package format

- **ES modules only.** The package is `"type": "module"` and its exports have only `import` conditions, so `require()` can't load it. Import it through a bundler; the build targets ES2022.
- **Three specifiers.** Import only `@aicayzer/inkkit`, `@aicayzer/inkkit/core` and `@aicayzer/inkkit/style.css`. Other paths in the package aren't exported. TypeScript declarations are included.
- **Dependencies are bundled.** The package contains Milkdown, ProseMirror, Pele, DOMPurify and every other runtime dependency, so your app runs the tree that Inkkit tested. A fix in a bundled package reaches you only through an Inkkit release, and your own dependency audit doesn't see bundled packages.
- **No separate runtime installation.** Hosts do not install Pele or DOMPurify. Update Inkkit and rebuild your page and notices to receive bundled fixes.
- **Node.js 26 or later** is declared in `engines`, which applies to the tools that install and build the package. The editor itself runs in the page.

## Entries with and without diagrams

| Specifier               | Contents                                                                                                         |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------- |
| `@aicayzer/inkkit`      | The editor, with Pele previews for supported Mermaid syntax.                                                     |
| `@aicayzer/inkkit/core` | The same exports. It imports neither Pele nor DOMPurify; `mermaid` code blocks stay editable source, unrendered. |

Both entries use `@aicayzer/inkkit/style.css`. Import from one entry throughout your app: if any module imports `@aicayzer/inkkit`, your bundle includes Pele and DOMPurify. Setting `rendering.diagramPreview` to `false` turns previews off but doesn't remove either library from the page. For what the core entry does with diagrams in copies and print, see [Markdown support](/concepts/markdown#mermaid).

### Page size

The main entry includes the diagram renderer and sanitizer; the core entry excludes both. The packed-consumer check records the exact byte size of both offline pages for each release. Measure your own page after bundling, because host code and build settings also affect its size.

## License notices

The package carries these license notices:

- `LICENSE`: Inkkit's MIT license.
- `NOTICE`: the notice for the table styles that Inkkit adapts from prosemirror-tables, and a pointer to the file below.
- `dist/THIRD-PARTY-NOTICES.txt`: the name, version, license and license text of every package bundled into either entry. The package build generates it from the bundled modules.

Ship `dist/THIRD-PARTY-NOTICES.txt`, `LICENSE` and `NOTICE` with your app. The generated notices include Pele, its included Lucide ISC notice and DOMPurify. `dist/THIRD-PARTY-NOTICES-FULL.txt` remains available with the same contents for existing host copy recipes. Also collect notices for dependencies your own host bundles; see [the web-view guide](/guides/web-view#carry-the-license-notices).

## Versioning

Inkkit is before version 1.0. Pin an exact version, for example with `npm install --save-exact`, and read the [release notes on GitHub](https://github.com/aicayzer/inkkit/releases) before you upgrade. They describe public API changes and any migration your app needs.
