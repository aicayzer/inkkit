# Preservation and clipboard behavior

Unedited documents retain their original bytes: saving one returns the loaded text without rebuilding it. Edits retain unchanged source blocks, original gaps, supported line endings and definitions. In a document with CRLF line endings, an edited block, including front matter, HTML and other literal Markdown, is written with CRLF. An edited block keeps its own authored syntax when blocks beside it are inserted or deleted; InkKit pairs it with the original block it most resembles. It does so wherever the edit is, including in a document that ends with an empty paragraph. An inserted block that resembles that original more closely can take its place, and the edited block is then written in canonical form. When a block repeats, which copy was edited, inserted or moved can be ambiguous, and that copy can be written in canonical form. Two lists of one kind side by side are one list in Markdown unless their markers differ, so an added, moved or rewritten list takes a bullet (`-`, `*` or `+`) or ordered delimiter (`.` or `)`) that its neighboring lists do not use. An item added to an authored list, or rewritten within it, takes that list's marker. This applies at any depth, such as a new sublist beside another or a new list between two lists in a quote. An unchanged list keeps its marker unless it would otherwise merge with a neighboring list across a boundary that a move changed, for example when two lists swap or the block between two lists moves elsewhere. Deleting the block between two lists with the same marker is refused rather than changing either list, even when the same edit moves other blocks. A `---` thematic break that would open the saved document while another `---` line follows it is written as `***`, because hosts would otherwise read it as front matter. This changes the bytes of an authored rule that comes to open the document, or that a new `---` line comes to follow. The reconstructed source is reparsed before it is returned. If safe reconstruction is impossible, the editor reports a preservation error; the host must retain the document rather than save an incomplete result.

Typing in one line of a paragraph keeps its other lines as written, including the indentation of continuation lines in list items, footnote definitions and quotes, and spaces at the end of a line.

Ending a list or quote in the middle splits it in two, and each part keeps the authored source of the items or blocks it holds. The second part of a numbered list continues from the first, so items numbered in sequence keep the numbers they were written with. A numbered list that comes to start from another number, such as after Shift+Tab lifts an item out of it, keeps the source of its items and is numbered from there. Enter in an empty item in the middle of a nested list moves the item out one level, as it does at the end of a nested list, and the items after it become its own; a numbered list that comes to follow the first line of an item starts from 1, because Markdown reads a list there only when it does. Backspace in the empty line or item left by ending a list joins the two parts again. A part keeps the source of its untouched items when items are later added at either end or its first and last items are edited. InkKit places each part in the original by the items it holds, never on items the other part kept. When repeated items leave more than one place that would give the part different source, the part is written in canonical form rather than with another copy's spelling. Ticking or clearing a task changes only its box. Joining two lists keeps the source of every item; the items of the second list take the first list's marker.

Mermaid is stored as ordinary fenced code. Previews do not change revisions or source. Body edits retain authored fence characters, lengths, information strings and line endings; a fence grows when the edited body would otherwise close it. Invalid or unsupported diagrams retain their source through snapshots, save/reopen and undo. Complete diagram Markdown selections preserve authored fences; partial source selections retain selected code text.

Unsupported syntax, raw HTML, frontmatter, unresolved references and unmanaged image references remain editable literal Markdown within a formatted document. So does a top-level block that the editor can't build in full, such as a list or quote with an item it can't show; the rest of the document stays formatted. Text typed into a literal block, Markdown characters included, is saved as typed, and the lines of the block that the edit doesn't reach keep their authored spelling. Enter at the end of a literal block starts an empty paragraph after it. When an edit changes what a literal block's text reads as, for example by removing its last unresolved reference or inline HTML, or by typing a blank line or a heading line into it, the editor reads the text again, as it reads in the note with the note's definitions, and shows the blocks it holds, in the same undo step as the edit. Blocks read again this way can be written in canonical form, for example `__bold__` as `**bold**`; other blocks keep their bytes. If the edit would be refused with the blocks read again, it is made without reading them again. Front matter stays literal while it is edited. An edit that still can't be reopened as the document, such as a line break at the end of a literal block or text that would change how other blocks read, is refused with `preservation`. If part of the Markdown can't be kept that way, `loadDocument()` and `reloadDocument()` throw `preservation` and leave the loaded document unchanged, rather than load a document that lacks it. HTML is not executed. An ordinary HTML clipboard round trip retains those literal blocks rather than turning them into fenced code. Author-created spacer paragraphs survive saving and reopening.

Footnotes and full, collapsed and shortcut reference links retain authored labels and shared, unused definitions. Editing implicit link text expands only that occurrence to a full reference when needed to retain its target. Definition edits update every reference to that label. An edit that keeps the title keeps authored angle brackets around the destination; a destination gains them when it needs them, such as for a space. Undo restores the original source. A link reference definition directly followed by a setext heading keeps both blocks' source.

Selection Markdown includes the definitions required by the copied references, including dependencies in footnote bodies. InkKit HTML carries inert reference metadata for its own paste path, which uses it only when it shows the same content as the HTML it came with. Other applications can discard this metadata while retaining semantic links and readable footnotes. Pasted label collisions rename incoming labels and definitions together without changing existing targets. Private image references are excluded from HTML metadata.

Ordinary Copy exports readable text and semantic HTML. Copy as Markdown explicitly exports source. Literal `&#x20;` in code or TXT stays literal; Markdown entities are interpreted by the parser where appropriate. No global entity replacement or edge-space trimming occurs.

Shift+Enter keeps a line break in the formatted document and in Undo history. At the end of a paragraph, including one in a list, quote or callout, the break stays pending: snapshots omit trailing Markdown breaks until content follows them. CommonMark cannot represent those trailing breaks, and a lone `<br />` is InkKit's empty spacer paragraph. Saving or leaving the paragraph therefore keeps its completed text; reopening that snapshot omits the pending empty line. Typing after the break completes it as an ordinary Markdown hard break in the same paragraph. Each Shift+Enter is a separate undo step, separate from typing before and after it. Repeated presses keep their line boundaries instead of splitting the paragraph. Tables and headings use `<br />` for new breaks so table rows and ATX headings stay on one source line. Authored HTML breaks keep their spelling, including at the end of a paragraph.

Tables retain cell boundaries. A `<br>` line break in a cell keeps its authored spelling, and Shift+Enter in a cell inserts one written as `<br />`. A row with fewer cells than its header stays short until one of its missing cells gains content. A table with a row that has more cells than its header remains literal source, because GFM ignores the extra cells. A `|` inside a code span is a common cause; escaping it as `\|` makes the table editable. Unsupported HTML tables, including merged cells and nested block content, remain literal source. Managed images export portable bytes in HTML and native image slots. Private display URLs are not exported as external image URLs. An unavailable image retains alt text and reports the failure.

Mixed image paste preserves surrounding text and commits one transaction. A result for a stale document is rejected. Native hosts must retain original clipboard content until export succeeds and keep imports bound to the captured document.

Supported callout markers, titles and fold markers remain in source. Folding and comment visibility are presentation changes, so they do not affect snapshots or undo history. Highlights retain their source delimiters and adjacent formatting. Unsupported callout variants remain editable literal Markdown; see [supported syntax](supported-syntax.md).

Complete HTML and Obsidian comments remain editable author content. While hidden, a comment survives Backspace, Delete, word or line deletion and any other edit from a caret beside it; deleting or replacing a selection removes the hidden comments inside the selection, and Undo restores them. Ordinary clipboard text, HTML and its inert metadata exclude comments, including comments inside required footnote definitions and preserved literal blocks. Explicit Markdown copy and snapshots retain them. Print hides comments even when revealed and includes collapsed callout bodies without editor controls. Incomplete delimiters, escaped syntax, code and TXT remain literal.

When comments occur inside an authored reference label, ordinary sharing removes that label's reference provenance while retaining its semantic link target. Comment-free labels retain their authored reference form in InkKit's HTML paste path.

Footnote identifiers and link destinations remain literal values under the Markdown grammar, including delimiter-looking text. This preserves their authored identity; comments in footnote bodies are excluded from ordinary sharing.

Changing a block between a paragraph or heading and a code block keeps everything the block holds. A paragraph or heading that becomes a code block, through `format('codeBlock')` or by typing a fence at its start, keeps the Markdown source of its text as code: author comments, footnote references, links, images, wiki links, formatting and line breaks stay as written. The code leaves out the heading's `#` marker and the markers that a quote, callout or list item adds to each line. Code that becomes a paragraph or heading keeps its characters as text and each of its lines as a line. Backspace or Delete that joins code with a paragraph or heading changes the second block the same way before joining them; Backspace at the start of a heading first lowers the heading. Block comments and preserved literal blocks keep their syntax: formatting commands don't change their type, and Backspace or Delete doesn't join them with a different kind of block. A comment hidden beside the caret refuses the change, as other edits beside it do; a selected block changes with its hidden comments in the code. A result that can't be saved and reopened as the same text, such as code with two spaces before a line end, is refused with `preservation`.

Printable output uses the complete frozen document model rather than the rendered editor or its selection. It includes folded content and excludes comments even when revealed. Exporting does not change source, revision, folding or undo history. Portable assets are copied and decoded before completion; unavailable authored assets reject the whole export. Invalid diagrams retain readable code with explicit warnings. An edit, undo or document replacement during export rejects the stale result.

Table movement and sorting retain complete cells and authored spelling of unchanged moved rows/cells where safe. Adding or deleting a row keeps the other rows and the delimiter row as written, including a row added directly after the header. Adding, deleting, moving or aligning a column changes every row, so each cell keeps its text and the table is padded afresh. Each operation is isolated from neighbouring edits in undo history. Spreadsheet paste replaces and grows a rectangular region without flattening cells. Unsupported clipboard tables inside an editable table reject with `preservation` before changing any cell; the host retains the captured clipboard for an explicit alternative. Outside a table, unsupported HTML continues through literal preservation.

Source editing keeps complete authored Markdown separate from its formatted interpretation. Unsupported and incomplete source remains saveable. Spelling-only edits are undoable even when the formatted tree is unchanged; returning to the loaded exact source clears dirty state without resetting revision. Switching modes preserves document identity and history.

Replacement preflights formatted source reconstruction before changing the document. Source/TXT replacements remain literal; formatted replacement does not rewrite attribute metadata or cross structural boundaries. A failed replacement leaves the complete original document intact. Heading entries are scoped to the current document, revision and editing mode; navigation changes presentation and selection only.

Read-only and text-input policy changes preserve exact source and shared history. Entering read-only invalidates pending imports and deferred Cut deletion even if editing is later restored. Failed mutation or composition-policy transitions leave the document unchanged. Command availability is observational: reading it or receiving its event does not change revision or dirty state.
